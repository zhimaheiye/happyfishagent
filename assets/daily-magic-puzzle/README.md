## 三、两个硬注意事项

1. ⚠️ **未落子前盘面可能每 60 秒自动重随机**（游戏内 `MiniGameController::tryToRandNewGame()`）。
   → **抓帧 → 识别 → 求解 → 执行必须一气呵成**，中途别留复核空档；否则算出来的解会打空。
   （2026-09-22 在 16 块档观察到跨小时 md5 完全一致，疑似只有 4 块档会随机 —— 待验。）
2. ⚠️ **起始页那张「整图」是缩略预览，不能当模板**（尺度与明暗都和实际拼块不同，任何缩放都匹配不上）。
   但**可以当「标准答案」**：把 ▶ 用掩膜挖掉后与打乱帧做 **高通 NCC**，再用**匈牙利算法**求全局最优一对一匹配。
   - 比图形**一律用 NCC，不用 MAE**（MAE 会被亮度差淹没，信号变噪声）。

## 五·B 🔴 中央四块的模板被 ▶ 掩膜挖掉了 ~80% —— 这是低 NCC 的根因

`tools/puzzle_solve2.py:41-45` 的实际常量（**照抄代码，不是我推的**）：

```
GX = [410, 502, 594, 686, 778, 870]      # 6x6 各列中心 x
GY = [127, 220, 312, 405, 497, 590]      # 6x6 各行中心 y
CELL = 92 ;  CXC, CYC = 640.0, 358.5 ;  R_HIDE = 92.0 ;  H = 44   # 模板 88x88
```

- 4×4 的 16 个块模板取自参考帧**中央 r2c2~r5c5**（代码 line 142-147：`cx, cy = GX[c-1], GY[r-1]`，r,c 各从 2 到 5）。
- ▶ 圆心 `(640, 358.5)` = `(GX[2]+GX[3])/2, (GY[2]+GY[3])/2` → **正好是中央四格共用的那个角**。
- `R_HIDE = 92 = CELL` → 掩膜圆 = 中央 2×2 的**内切圆**。
- 逐像素重算（`H=44` → 88×88 模板）：

| 块 | 落在 | 中心距 ▶ | 模板**保留** | 被挖掉 |
|---|---|---|---|---|
| 块6 | r3c3 | 65.4px | 1612/7744 = **20.8%** | **79.2%** |
