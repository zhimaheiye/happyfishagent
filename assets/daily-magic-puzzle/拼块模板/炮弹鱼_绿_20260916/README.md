## MAA 使用说明

模板直接从**打乱后**的 1280×720 原帧裁剪，与游戏实际渲染 1:1，可直接用于 MaaFramework 的 `TemplateMatch`。

- **格式**：RGB PNG，**无 alpha 通道**（避免 OpenCV 读成黑底），无缩放、无压缩伪影。
- **分辨率**：必须 **1280×720**。游戏按其它分辨率渲染时模板尺寸需等比缩放，否则匹配不上。
- **建议 `roi`**：棋盘外框 ≈ `[346, 82, 920, 654]`（`[x, y, w, h]`）；想更保险就逐格限定到列中心 `x = 431 / 570 / 709 / 847`、行中心 `y = 150 / 288 / 427 / 565` 的 138×138 邻域。
- **阈值**：本套 4 块之间相似度偏高（大面积星空纹理），`threshold` 建议 **0.85** 起，误报就升到 0.9。
- **匹配到的坐标**：模板中心 = 该格子中心，可直接按 `col = round((x - 431) / 138) + 1`、`row = round((y - 150) / 138) + 1` 换算成格号。

## 重新生成的命令

```bash
python happyfish-activity-automation/scripts/piece_numbering.py \
  --idle 原料_未开始.png --shuffled 原料_打乱后.png \
  --xs 431,570,709,847 --ys 150,288,427,565 --cell 138 \
  --btn 639.5,357.5 --btn-r 95 \
  --out-dir . --prefix 炮弹鱼_绿 --label "炮弹鱼（绿）"
```

脚本用「未开始帧的中央 2×2（挖掉 ▶ 圆）」当标准答案做 NCC 比对，自动定出正确排布并发编号。
本次实测 **NCC = 0.904，次佳 0.737**（领先 0.166，已人工看图核对：拼出来是一条完整连贯的鱼）。

> ⚠️ **别用「饱和度均值」判空**：本轮这只鱼的星空块饱和度均值只有 55~70，会被判成灰格
> （自动阈值 86.2 只找到 2/4 块）。脚本已改用 `彩色像素占比 + 灰度std/100` 作判据，
> 拼块 1.33~1.54 vs 灰格 0.14~0.27，断层 1.051，干净利落。
