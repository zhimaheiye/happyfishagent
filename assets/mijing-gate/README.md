## 四、四个要点（看图时对照）

1. 🚩 **`需要：A/B` 的 A/B 语义「未定论」**，两种读法在两帧里各只能自洽一种 → **定死前不许写进自动化判据**。详见下面「四之一」。
2. **权威判据 = 选鱼面板**，不是卡片上的 `需要：A/B`。但面板自己的「已经选中 N/M 条鱼」到底 M 是「需送数」还是「面板可选卡数」，也随第 1 条一起存疑。
3. ⛔ **按钮显示「钞票 xN」= 开心宝**；且**「送出」与「钞票 xN」是同款绿色胶囊** → 必须 OCR 读字，不能靠颜色（2026-10-08 实测踩到，见「五」）。
4. **送出 / 删单后槽位立刻补新单**，且新单是「倒计时 + 钞票 xN」**锁定态** → **不处理**。

## 四之一、`需要：A/B` 的两帧矛盾（2026-10-08 复核，把 10-06 的结论降级为「待核」）

本目录 `02_` 与本档 `20261008_03_` 摆在一起对，同一个字段**只能各解释得通一种读法**：

| 帧 | 卡片 `需要：A/B` | 面板 header「仓库里的X **H**」 | 面板 footer「已经选中 **N/M**」 | 「☑ 选中幼鱼」 | 网格里卡片的鱼态 |
|---|---|---|---|---|---|
| 10-06 树须泡泡(粉)（`02_`） | `75/7` | **4** | **4/7** | ☑ 勾着 | **只有 4 张，全是「幼鱼」** |
| 10-08 神仙鱼(紫)（`20261008_03_`） | `38/49` | **49** | **0/49** | ☑ 勾着 | 满屏 5 列，**每张都写「成年鱼」** |

- 读法 **OLD**（本目录旧版 §四、`活动档案/秘境之门.md` §3/§13.5、SKILL.md 全按这个写）：
  **A = 拥有总数，B = 需送数**，footer 的 **M = 需送数**。
  → 10-06 完美吻合：需送 7、幼鱼只有 4 → `4/7`；当时判「鱼苗不够 → 删单」，**处置结果反过来印证了 M=需送**。
  → 但 10-08 说不通：A=38 是拥有，header 却写 49。
- 读法 **NEW**（10-08 当时临时下的结论，已撤回）：**A = 需送数，B = 拥有数**，footer 的 **M = 面板可选卡数**。
  → 10-08 吻合：拥有 49（header=49=网格张数）、需送 38。
  → 但 10-06 说不通：那样 M 应该等于需送 7 而面板只有 4 张卡，`4/7` 的 7 就成了「拥有数」，与 header 的 4 冲突。

### 怎么一次性定死（零消耗，不需要真送鱼）

1. 进选鱼面板，**同屏读四个数**：卡片 `A/B`、header `H`、footer `N/M`、**网格卡片实际张数 T**。
   - `M == B` → OLD（M 是需送数）；`M == T` 且 `T == B` → NEW。
2. 把「☑ 选中幼鱼」**取消勾选**，看 **T 变不变**：
   - 变了 → 它是**显示过滤器**（10-06 那帧只显 4 张幼鱼就是这个原因）；
   - 不变 → 它只是**自动勾选偏好**（那 10-08 的 49 张成年鱼就是全部拥有量）。
   ★ 这条是两帧矛盾的**唯一可疑变量**，不做这一击就永远定不了。
3. 顺手记 `奖励 水晶xN` 与 A/B 的关系（10-06 是 `75/7` → 水晶 x7，看着像 **B** 而不是 A）。

### 定死之前的默认动作

**没这条鱼 → 删单；有鱼但不够 → 也删单；判不清 → 什么都不点，留给芝麻。**
⚠️ 另外：卡片上的绿「送出」**不直接送鱼**，而是进逐条挑鱼窗（见「五」第 3 条）→ 这一步本质是红线里的「挑哪条鱼」= **代选**，自动化默认**不点**。

1. 送鱼获得绿水晶（大意：完成订单可获得水晶回馈）。

5. ★「**送出皇冠鱼不会获得皇冠哦。**」
