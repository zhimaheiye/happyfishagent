1. **消耗体力可以参与烤月饼**，获得三种馅儿的月饼，可用来兑换**碧岚桂花酿**；

## 做月饼消耗型入口分支建模（2026-09-25 下午）

> 本轮核心：做月饼 != 普通导航，它是 resource_consuming 入口。模型见 metadata.json（含状态语义、资源、门禁、确认框路由）。不扩展 Recorder/compiler/takeover 框架，不做通用资源系统。

### 业务修正（芝麻 2026-09-25 下午）

**退出确认框 = 业务状态路由，不是固定安全策略**：

    MooncakeGameInProgress
      ↓ 请求退出（✕）
    MooncakeExitConfirm
      ├─ round_status=in_progress  → 暂时离开 → ActivityMainResume（主页变「继续游戏」，可恢复）
      ├─ round_status=complete     → 结束游戏 → 结算/主页恢复「做月饼」→ 下一轮可开始
      └─ round_status=unknown      → 不点任何按钮 → Stop/Takeover（AI 继续观察）

- 禁止「出现确认框永远点暂时离开」（上一局永久未结束 → 永久「继续游戏」→ 无法开新局的业务死锁）。
- 禁止「永远点结束游戏」（探索中未完成局会被提前结算，丢失进度）。
- 「去下一步骤」语义待实机确认（疑似当前制作步骤完成后进入下一阶段的推进按钮），不得永久禁用。
- 核心问题：AI 怎样从画面可靠判断这一轮是否完成（见下）。

### 资源门禁（第一版二态）

- metadata.json → permissions：activity_stamina=false、small_hand_tool=false，默认全部禁止。
- 授权入口：gate_check.py --allow-resource activity_stamina（一次性）或编辑 metadata。
- 识别资源 ≠ 获得消费授权。缺授权时：识别 → 门禁 DENIED → 不点击 → Stop。
- 继续游戏 ≠ 新消耗：从 ActivityMainResume 恢复现有局不得再扣体力（实机验证体力不变）。
- 不做 budget / reserve / daily_limit（等第二个真实消耗型活动出现再抽象）。
