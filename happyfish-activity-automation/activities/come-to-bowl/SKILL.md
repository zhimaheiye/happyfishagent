## 〇、一句话结论（以后先读这句再决定要不要动手）

**主页原文：「每消耗 [钞票]x8 可获得：[碗]x1」。**
→ **钞票 = 开心宝马甲**（绿野/课间/裁缝铺/刺刺四档互证）。这句话挂在活动主页正中，等于官方写明：
**这个活动的主要投入是开心宝，不是体力、不是次数。**

所以 agent 的默认动作 = **不碰主循环**，只做两件免费的事：
1. **切掉手上已有的"碗"**（`剩余：碗xN`，是**已经发下来的免费次数**，不是要现买的）→ 产 **水滴 / 水果币**；
2. 去「去领奖」**只读**水滴/水果币余额、兑换候选和价格，**保留给用户决定兑图纸、拼图或其他物品**；不擅自交易。

📌 **本档实测**：`剩余 碗x9` 是**进活动前就存在的**（当天没为它花过 1 个开心宝）。**先去看这个数，再决定做不做** —— 有碗就切，没碗就撤。

## 二、⭐ 本档最重要的产出：**"免费选一个"的百宝箱，同时就是付费货架**

> ✅ **2026-10-11 现行授权**：A/B 形态中**唯一不标价的免费随机箱**可由 Agent 自行选一个打开并收取掉落；其它带钞票价签、全开/全买、额外付费次数始终不点。选择免费箱前应现帧确认确有明确免费项，不能只看颜色/历史位置；若实际上是**明示不同永久物品的多选一**而不是随机盲盒，则不代选。去领奖的永久兑换仍归用户。

百宝箱（切够 `水果碗` 后点左下宝箱触发）**有三种形态，全部带付费钩子**：

| 形态 | 长相 | 免费钮 | 付费钮（⛔ 全不点） |
|---|---|---|---|
| **A 五选一 + 四箱标价** | 「成功触发百宝箱 / 百宝箱中奖励多~选择一个百宝箱打开它吧！」5 个箱子 | 点任意一个箱子 → 该箱显示 **GET**（本档拿到 **水滴x10**） | 另外 4 个箱子各自带 **钞票价签**：`钞票x22 / x9 / x3 / x9`，下方还有 **「原价 钞票x43」划掉 → 「钞票x30 一键全买」** |
| **B 五选一 + 一键全开** | 「必有1个百宝箱有水果币！试试运气吧~」+「百宝箱随机小鱼：X」 | 点一个箱子（本档拿到 **水果币x3**）；有时直接弹「恭喜获得百宝箱奖励：**西瓜鱼x1**」+「确定」 | **「钞票x12 一键全开」** |
| **C 果汁膨胀（二选一）** | 「发现果汁！ [水滴]x3 → [水滴]x?」 | 绿钮「**放弃膨胀**」`(413,490)` → 按 x3 收下 | 粉钮「**钞票x2 膨胀**」`(846,490)` → 花开心宝翻倍 |

🚩 **判据同主技能红线 1**：形态 A 的 5 个箱子**长得一模一样**，区别只在箱子下面**有没有钞票价签**；
形态 C 的两个钮**一绿一粉**，绿的才是免费的 —— **颜色在这里恰好和"免费"对上了，但不能靠颜色，要靠价签**。
⚠️ **形态 A/B 关掉时不要顺手点屏幕中下方**：`一键全开 / 一键全买` 就压在 `(640,585)` 附近，
和"确定/收下"的位置只差几十像素。**每次先看图，再点。**

## 三、百宝箱会**锁住切水果**（本档踩了两次才知道）

- 现象：`水果碗` 达到阈值后，**滑动不再触发切割**（剩余碗数不变、目标 % 不变），左下宝箱上会挂一只**白色手型光标**。
- 📌 **处置**：**先点宝箱把这一轮开掉**，回去才能继续切。
- ⚠️ **阈值是递增的**：本档实测 `8 → 15 → 20 → 30 → 50`。所以**不是"每 8 个碗开一箱"**，越往后越难。
- 📌 因为开箱会打断，**批量脚本每切 1 刀就要看一眼 `A/B`**，否则会出现"连划 5 下只中 2 下"的假象（本档就这么白扔了 3 刀的判定时间）。

## 四、「大碗好礼」= 开心宝累计消费阶梯，**一档都不做**

- 页首「已消费：钞票x25」← **这是本账号在该活动内的开心宝消费计数**（本档没动它）。
- 四档：`累计消费 钞票x49 → 宝石x1 + 钞票x10`、`x128 → 果盘x1 + 拼图x18`、`x258 → 鱼x1 + 碗x10`、`x368 → 大象x1 + 鱼x1`。
- 下方「小目标 (3/11)：今日消费 钞票x10 → 碗x2」+「累计达标8个消费小目标 → 鱼x1」。
- 🚩 **注意第一档的奖励里就含「钞票x10」** —— 用开心宝买开心宝的错觉设计。**别把它当"回本"**。
- **处置**：整页只看不点，X 关掉。⚠️ 本页 X 在 `(1240,78)`。

## 五、免费侧门：切碗 → 水滴/水果币 → 去领奖（最后一步仅记录，不代兑）

本档全程账（**开心宝 345 → 345**）：

| 步骤 | 前 | 后 |
|---|---|---|
| 剩余 碗 | 9 | **4**（切掉 5 刀） |
| 水滴 | 0 | **24**（切刀产 1/5/5/2/5 + 百宝箱 A 形态 +10） |
| 水果币 | 0 | **1**（百宝箱 B 形态 +3，兑拼图 -2） |
| 水果碗计数 | 0 | 43/50（未再达阈值） |
| 历史已发生的到手实物 | — | **图纸x1（水滴x2）+ 拼图x1（金币x2）+ 西瓜鱼x1（百宝箱直发）**（当日事实留档，**不构成未来自动兑换授权**） |
| 商人订单 | 0/20 | **4/20**（每切 1 刀 = 1 单，**这就是"商人订单"的来源**） |

- **「去领奖」的兑换有正规的「取消」钮**：点亮的价签 → 弹「确定要兑换吗？ [水滴]x2」→ 绿「取消」`(360,583)` / 粉「确定」`(913,583)`。
  → ⚠️ **此处虽然有取消钮，但不意味着 Agent 有权点“确定”**：这是把活动货币换长期资源的最终兑换，只能等用户指定奖品与数量后执行。与刺刺大作战那个“只有确定、没有取消”的窗相比，此处按钮结构不同；**是否授权与有没有取消钮无关**。
- 「去领奖」右上 8 格里本档余额**只够 `水滴x2` 和 `金币x2` 两格**，其余 6 格当时需 50~188，**本档当时余额不足**。**够买 ≠ 获得兑换授权**，不要为了试价签而点。到活动临期须核实截止时间并提醒用户选号。

## 六、⚠️ 手法坑

🚩 **手法 1 · 滑动切水果要够慢**：`duration=200/300` 的滑动**经常完全不注册**（画面毫无变化，也不扣碗）；
`duration=600` 稳定生效。**判"这一刀有没有切"只看 `剩余：碗xN` 有没有 -1**，别看水果有没有裂开（它本来就会换）。

🚩 **手法 2 · 切割方向 = 沿水果长轴垂直切**：
- **香蕉**（横长轴，包围盒 `x≈495~760, y≈320~445`）→ **竖向**划，`x = 495 + 目标% × 265`；
- **葡萄**（竖长轴，包围盒 `y≈275~490`）→ **横向**划，`y = 275 + 目标% × 215`。
- 本档两刀"接近命中"分别拿到 **水果碗 5** 和 **15**，误差越大给得越少但**不会为 0** → **不用追求 PERFECT，先保证切到**。

🚩 **手法 3 · 这个 Recorder 会话里 `swipe` 子命令没落新状态**（`--safety readonly tap` 也偶发 `refused`，
**同一条命令原样重跑第二次就会执行**）。批量脚本里对 refused 要**自动重试一次**，否则会误判"点了没反应"。
