## 二、单关流程与"现量"要求

### 2.1 关卡任务条（顶部「第 N 关任务」三格）
- 三格 = `收集 蓝音符x3` / `采集满 0/M 个音色舱` / `收集 红音符x5`（M 随关数变）。
- 三格下方是**奖励位** `耳机x1` / `耳机x2` / `礼盒x10`；达成后打绿色「**GET**」标。
- 底部提示原文：「每个音色舱都可以采集一次，**金色音色舱里有特殊的红色声波奖励哦！**」
  ⇒ **红音符只从金色舱出**；本档三关的舱色序列 = 粉(蓝音符) / 粉(橙音符) / **金**(红音符)。
- 左上角四行计数器 = `耳机 / 蓝音符 / 橙音符 / 红音符` 各 xN，**这是本活动唯一的产出读数面**。

### 2.2 采集阶段
- 左下橙「**采集**」= ✅ 免费，每舱一次。
- 🔴 **坐标坑（本档实测）**：「采集」钮的 **x 跟随"最左侧剩余音色舱"横移**，钮中心 ≈ 舱中心 − 10px，y 恒 ≈557。
  本档 L1 实测钮心依次 ≈ (270,557) → (533,557) → (767,557) → (1012,557)。
  ⇒ ⛔ **禁止复用上一帧坐标**，每次采集前拍一帧、量一次、点一次。
- 采集后**可能**弹「是否带走」：
  - 左「**放弃**」= ✅ 免费（本档实测钮心 (527,428)，⚠️ 现量）；
  - 右「**钞票 xN 带走**」= ⛔ 开心宝。
  - ⭐ 放弃后该舱消失，但**计数器与 GET 标照常累加**，「带走全部」价签同步下降（钞票x6 → x4）
    ⇒ **价签下降 = 你放弃了，不是"便宜了可以买"**。

### 2.3 调试阶段
- 每关采集满后进入；本档见 **4 台**（2 台蓝音符 + 2 台红音符），每台下方**并排两枚一模一样的「选择调试」**：

| 钮 | 助手 | 成功率 | 价签 | 判定 |
|---|---|---|---|---|
| 左 | **学徒小精灵**「还在学习调音技巧，经常搞不定音色和节奏」 | **66%** | **无** | ✅ 本档全用它 |
| 右 | **完全体精灵**「已熟练掌握调音技巧，能调试出完美的音乐」 | **100%** | **蝴蝶x20** 或 **钞票x2**（同屏不同台角标不同） | ⛔ |

- ⭐⭐ **两枚钮形状/字号/底色完全相同 ⇒ 唯一判据是"钮上有没有价签角标"。颜色不是判据、位置也不是判据。**
- 中部「**本次成功率：N/M**」= 本关调试计数。本档出现 2/3 ⇒ **学徒会失败**；
  失败**不扣钱、不重开关卡**，只是该台没调成（底部原文「调试失败无法恢复哦！全部调试成功可以累积成就哦~」⇒ 损失的是"成就"，⛔ 不构成点付费钮的理由）。
- 右下「**完美调试全部 钞票x5**」= ⛔。

### 2.4 订单阶段
- **末关**（本档 L3）完成调试后主按钮文字变成「**去完成订单**」；非末关是「下一关」。
- 订单页：「队列中共有**10名顾客**-完成旋律订单获取奖励吧！」，一屏 5 张卡，每卡 `旋律x3`/`旋律x5` → 奖励 `蓝笑脸币x3` / `金笑脸币x2` / `蓝x6+耳机x2` / `金x3+耳机x2`。
  🔴 **10-19 把 10-18 那句"未核实"补上了**（10-18 配图 README 第 07 行早已如实记下"只有第 1 张卡下方有粉色完成钮，其余 4 张没有 ⇒ ⛔ 为什么不给钮未核实"）：本档两帧对撞证实 = **一屏只有一个可交位 = 队列最左**，交掉后**后面的补位上来**（10-19 实测：交 1 单后队列 8→7 名，新最左卡补位）。⇒ 正确说法不是"逐单点完成"，是"**交最左这一单**"。
- 顶部进度条原文 `0/100`、刻度 `10 · 30 · 50 · 70 · 100`，五档各挂一条鱼。⚠️ **计的是哪种货币未核实**（该帧左上三色计数器 `耳机x0 / 蓝x0 / 金x0` 而进度条已起步）⇒ ⛔ 别当"笑脸币累计"用。⚠️ 本条 10-18 06:4x 由 `1/10 · 10 · 20 · 50 · 70 · 100` 改过来 = 写档时把 `0/100` 误读、把 `30` 写成 `20`，**入库前逐张回看图才发现**。
  🔴 **10-19 补一条反证**：`1/100` 这一格在**交单前后两帧完全相同**（成交了 1 单、金币 0→2、队列 8→7 都没让它动）⇒ **它不是订单完成计数**，⛔ 别拿它当日任务进度。
- 每单下方粉色「**完成**」= ✅ 免费交单（10-18 点了 2 次；10-19 点 1 次成交）。
  🔴 **10-19 定性了钮色判据（仅对"最左可交位"成立）**：**粉 = 彩色音符库存够**（04:43 帧 最左需 `粉x3`、库存 `粉x9` ⇒ 粉）；**灰 = 不够**（成交后新最左需 `蓝x5+金x5`、库存 `金4` ⇒ 灰）。成交的铁证是三本账同时对上：**金币 0→2、粉音符 9→6（正好扣 3）、队列 8→7 名**，而 `钞票x31` 全程未动 ⇒ 交单确实 0 付费。
- 🚩 底部橙「**完成全部 钞票x31**」= ⛔ 一句话买通全部订单。⚠️ **10-19 反例：它是常驻大 CTA，钮面「粉色」不随可交状态变化**（同屏唯一可交位已灰时它仍粉）⇒ **别把「完成全部」的颜色当"有没有单可交"的判据**，判据只看最左那张卡的钮。
- 🚩 每交完 1 单弹「**顾客带了额外特惠奖励~**」窗：同屏 4 个付费控件（`钞票x3`/`x5`/`x5` + `SALE 钞票x10带走全部`）、**0 个免费钮** ⇒ **唯一动作 = 右上白 X**。

### 2.5 兑换页（「兑奖」）
- 两页签 = 蓝笑脸币 / 金笑脸币；本档读到 `蓝x180 / x150 / x150 / x2`、`金x180 / x150 / x150 / x1`，部分格另挂 `⚪1` = 需 1 张金券。
- 🔴 **10-19 定性了价签颜色约定**：**粉色价签 + 右上角黄色加号角标 = 当前余额兑得起**（`蓝币x2`、`金币x1` 两格）；**灰色价签 = 兑不起**（180/150/150 六格）。⇒ 一眼判"可兑项"不用逐个试。
- 右侧「**累计1/8天开启20个耳机包，今日已完成**」+「领取」钮呈**灰色**。
  🔴 **10-19 解除 10-18 的未验证标注**：本档读到的是 `累计1/8天开启20个耳机包　今日已开启：10/20` + 奖励鱼 `x1` + **灰「领取」** ⇒ 灰态原因已明 = **累计天数 1/8 未到**，⛔ 不是"已领取"。
- 本档**一个没换**：可负担项只有 1 个（蓝笑脸币x2），而**兑换对象（鱼 vs 装饰）属芝麻偏好** ⇒ 按「不代选/不代领」原样留给芝麻。10-19 同样两件兑得起（卷轴 蓝币x2 / 拼图 金币x1）**留给芝麻**。
