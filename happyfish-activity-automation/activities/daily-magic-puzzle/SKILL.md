## 二、核心规则（全部实测）

1. **不是拖拼块** —— 是**整行 / 整列循环平移**：横滑某行 → 该行横移，右侧绕回左侧；纵滑某列同理。
2. **滑动方向 = 内容移动方向**（往右滑 = 内容往右走）。
3. **滑动距离 = 平移格数**：138 px ≈ 1 格。
4. **目标**：4 块拼成正确的 2×2 图。**不必回中央**——任意位置的 2×2，只要相对排布对即可。
5. 灰格是可互换的空位，忽略。
6. **拼块不会被旋转**（散开前后内容逐像素一致）。
7. 开局散块位置随机 → **每轮都要重新识别 + 重新求解**，不要背坐标。

## 三、求解流程（照做）

1. **截图** → 用 `../../scripts/piece_identify.py` 识别 4 块在哪：  
   `python piece_identify.py shot.png --tpl-dir <拼块模板目录> --xs 431,570,709,847 --ys 150,288,427,565`
2. **定正确排布**（已脚本化，一条命令）：
   `python ../../scripts/piece_numbering.py --idle 未开始.png --shuffled 打乱后.png --xs 431,570,709,847 --ys 150,288,427,565 --out-dir <目录> --prefix <图案名> --label <图案名>`
   - **原理**：**未开始帧的中央 2×2 就是正确排布**，只是正中压着 ▶ 圆钮 → 用圆形掩膜挖掉；再拿 24 种排布跟它做 **NCC（归一化互相关）**。
   - ⚠️ **起始页那张图不能当「模板」**去匹配拼块（是缩略预览，明暗/尺度都不同），**但可以当「标准答案」**——2026-09-15 实测 **NCC 0.928 vs 次佳 0.534**，信号极强。
   - ⚠️ **别用 MAE 打分**：两帧亮度差会把信号淹掉（24 种排布的 MAE 全挤在 75~78，差 0.6 纯噪声）。
   - 兜底 / 交叉验证：边缝连续性（接缝两侧像素相关系数）+ 把候选排布拼出来看图——正确的那张是一条完整连贯的鱼。
3. **BFS 求解**：  
   `python ../../scripts/line_shift_solver.py --n 4 --at "A=2,2 B=3,2 C=4,2 D=4,4" --shape "TL=C TR=A BL=D BR=B"`  
   （默认目标锁**中央 2×2**，这样「任意位置」和「回中央」两种判定都能满足。）
4. 按解逐步 `input swipe`（800~900 ms），**每步截图复核**（用第 1 步的脚本再识别一次）。
5. **拼成即停**：出现「完成」印章 / 彩带（约 3 秒后弹奖励窗）→ 本次自动化结束。**不点奖励窗任何东西**（见红线）。

首次实测解（A=鱼头 B=鱼身 C=鱼尾 D=水波，起始 A(2,2) B(3,2) C(4,2) D(4,4)）：
`行2右1 → 行3右1 → 列2上1 → 行4右2 → 列2上1` = 5 步通关。

## 五、素材与编号规范（每个新图案一份）

图案**每天刷新**，每个图案单独建目录，互不复用：

```
活动档案/拼图_每日魔幻拼图/拼块模板/<图案名>_<YYYYMMDD>/
    <图案名>_1.png ~ <图案名>_4.png      ← 拼块模板（138×138）
    <图案名>_编号示意图.png               ← 4 块拼合 + 编号标注（3x）
    原料_未开始.png / 原料_打乱后.png     ← 溯源原帧
    README.md                           ← 编号表 + MAA 用法
```

- **编号 = 正确排布的左→右、上→下**：`1=左上  2=右上  3=左下  4=右下`。
- 文件名**必须带图案名**（如「蛋糕鱼」），便于按名字挑模板。
- 模板一律从**打乱后**的原帧裁（未开始帧有 ▶ 遮挡，不能当素材源）；**138×138 满格裁切**，与游戏渲染 1:1。
- **MAA 硬要求**：RGB PNG、**无 alpha 通道**、分辨率与截图一致（1280×720），否则匹配不上。
- 换算：模板中心 (x,y) → 格号 `col = round((x-431)/138)+1`，`row = round((y-150)/138)+1`。
