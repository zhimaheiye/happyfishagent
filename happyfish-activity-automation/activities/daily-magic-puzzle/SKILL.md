## 二、核心规则（全部实测）

1. **不是拖拼块** —— 是**整行 / 整列循环平移**：横滑某行 → 该行横移，右侧绕回左侧；纵滑某列同理。
2. **滑动方向 = 内容移动方向**（往右滑 = 内容往右走）。2026-09-18 用「5 步解全部命中」再次验证。
3. **滑动距离 = 平移格数**：138 px ≈ 1 格。
4. **目标**：4 块拼成正确的 2×2 图。**不必回中央**——任意位置的 2×2，只要相对排布对即可。
   （求解器默认锁中央 2×2，两种判定都能满足。）
5. 灰格是可互换的空位，忽略。
6. **拼块不会被旋转**（散开前后内容逐像素一致）。
7. 开局散块位置随机 → **每轮都要重新识别 + 重新求解**，不要背坐标。
8. ⚠️⚠️ **未落子之前，棋盘可能每 60 秒自动重随机一次。**
   - 证据（2026-09-15，logcat）：`MiniGameController::tryToRandNewGame() k = 0` 连续 12 次，
     `15:50:30 → 15:51:31 → … → 15:57:32 → … → 16:00:32 → 16:01:32 (k=1)` 后停止，**间隔精确 60 s**。
   - 后果：**「打乱后」的截图只有 ≤60 秒保质期**。拿它慢慢分析会得到**过期坐标**。
   - 纪律：**截图 → 识别 → 求解 → 执行，尽量一口气跑完**；中间别去写文档、别去翻档案。
   - 执行前**再截一帧复核**：不一致 → 触发了重随机 → **重新识别 + 重新 BFS**（BFS 毫秒级，别心疼）。
   - ⚠️ **2026-09-16 反常观测**：点开始后 97 秒（11:55:45 → 11:57:22）棋盘**完全没变**（逐格模板识别 diff=0.0，
     两帧文件大小也一样）。与 09-15 的 60 秒连击不符 → 触发/停止条件仍**待复验**。
   - ⚠️ **2026-09-18 新证据（倾向于"确实会随机"）**：点开始后 1 s 抓的帧（`pz_shuf2`）与约 4 分钟后抓的帧
     （`pz_check2`）逐块识别结果**完全不同**；但**再往后连抓 4 帧（间隔 1.5 s）结果又完全一致**。
     → 合理解释：**重随机只在"刚开局的一段时间内"发生，之后停止**。
   - **结论不变：永远按"截图会过期"安排流程**，复核一帧的成本远低于拼错重来。

## ★ 三、4x4（16 块 / 6x6 棋盘）—— 2026-09-22 首次全通，走通即用这条

> ★★ **芝麻 2026-09-22 的硬要求**：**不要让用户去数格子报坐标**。
> 他要的是「**你自己对比进入前后两张截图，把每个块落在哪个格识别出来**」。
> 下面的流程就是按这条做的 —— 全自动，人只需要开局点一下 ▶ 和最后选奖励。

### 3.1 三种难度到底差在哪（纠正常见误解）

| 难度卡 | 图片块数 | **棋盘大小** | 未开始帧里拼好的图占哪几格 |
|---|---|---|---|
| 2x2 | 4 | 4×4（格距 138） | 中央 2×2（r2c2~r3c3） |
| 3x3 | 9 | 5×5（格距 109） | 中央 3×3 |
| **4x4** | **16** | **6×6（格距 92）** | **中央 4×4（r2c2~r5c5）** |

**棋盘会随难度变大**（不是始终 4×4）—— 旧版本技能写的「棋盘容器始终 4×4」**是错的**。

### 3.2 6x6 棋盘几何（与 MFA 官方 `PUZZLE_GEOMETRY_6X6` 逐值一致）

- 格心 x：`410, 502, 594, 686, 778, 870`
- 格心 y：`127, 220, 312, 405, 497, 590`
- 格距 **92 px**；棋盘 ROI = `(365, 82, 551, 554)`（x365~916 / y82~636）
- **格号 = 行优先 1~36**（r1c1=1 … r6c6=36）
- ▶ 圆钮中心 `(640, 358.5)`、半径 `92`（遮挡参考帧中央约 4 块）

### 3.3 两张截图分别是什么

| 帧 | 内容 |
|---|---|
| **进入前**（未开始） | 拼好的完整 4×4 排在**棋盘中央 r2c2~r5c5**，整盘被压暗，正中压着 ▶。**这张就是「标准答案」**：按行优先切 16 个模板，第 i 块的身份 = 正确排布里第 i 格 |
| **进入后**（打乱） | 16 块散落在 6×6 里，其余格是灰色 filler；盘面还有**一道大圆弧反光装饰**（静态） |

- **弧线装饰的坑**：它会让灰色格的一部分变亮 → 「非灰占比」读出来是 0.5~0.9，**看起来像有拼块**。
- **破法**：判据改成 **3×3 子块非灰占比的「最小值」≥ 0.75**（真拼块处处非灰；弧线只污染灰格的一部分子块）。
  实测：真拼块 min 子块 0.82~1.00，被弧线污染的灰格最高只有 0.58 → 干净分开，且**恰好 16 格**。
  这个判据还自带体检：**命中数 ≠ 16 就说明截图拍在散块动画中途**。

### 3.4 一条命令求解（★ 核心工具）

```
<venv python> tools/puzzle_solve2.py <未开始.png> <打乱后.png> [输出前缀]
```

产出：
- `<前缀>_out.txt` —— 候选格判据表 / 匹配矩阵 / 逐块结果与余量 / **MFA 位置串** / 自检
- `<前缀>_proof.png` —— 四面板证据图（参考帧 / 打乱帧带识别编号 / 参考拼图 / 重建拼图）
- `<前缀>_board.png` —— 棋盘大图，每格标「格号 + 第 i 块」，方便肉眼看一眼核对

算法（四步）：
1. 参考帧中央 4×4 切 16 个 88×88 模板（▶ 用圆形掩膜挖掉）。
2. 打乱帧里按 3.3 的判据找出 16 个候选格。
3. 「块 × 格」在格心 **±16px（步长 2）** 内做**高通归一化互相关**：
   高通 = 减局部盒均值（半径 14）。它一次干掉两层低频干扰 —— 参考帧的整体压暗遮罩 + 盘面那道圆弧反光；
   NCC 本身对线性亮度变化免疫。**判别力明显优于直接用原始 RGB 做 NCC**。
4. **匈牙利算法**求全局最优一对一匹配（每块只能占一格）。

三重自检（脚本自动打印，别跳过）：
- 每块「最优 NCC − 次优 NCC」的**余量**；< 0.02 会打 ⚠️。
- **重建拼图 vs 参考拼图**的 R²（全局仿射拟合，不逐块 → 不是循环论证）+ **30 次随机分配对照**。
- **接缝连续性**（内部接缝梯度 ÷ 块内梯度）。

> ★ **更硬的一招（怀疑结果时用）**：把参考图**反暗化**（对重建图做逐通道全局仿射拟合）后与重建图逐像素相减，
> 差值图除 ▶ 圆区外应基本全黑。09-22 实测掩膜内平均绝对差 **7.18 / 255**（纯压缩/抗锯齿噪声级）→ 铁证。

### 3.5 把位置串喂给 MFA（两条命令）

MFA 的「每日魔幻拼图」任务**不管进出导航**，它只做两件事：
① 用 `拼图页面_识别.png`（左下角浪花）确认你**已经停在棋盘页**（不在就 `StopTask` 安全中止）；
② 按你填的 16 个位置算最短 Swipe 序列并执行。所以**要先把棋盘开好、▶ 点完**。

```
# ① 写入 16 个位置（自动找到那 16 个 EditControl）
<venv python> tools/mfa_set_puzzle.py --read
<venv python> tools/mfa_set_puzzle.py --values "11,7,12,2,5,24,16,29,22,4,19,18,6,20,34,10"

# ② 单独运行任务（会暂停挂机队列 → 右键任务行 →「单独运行」→ 等结束 → 视情况恢复挂机）
<venv python> tools/mfa_zero_task.py --dry --task 每日魔幻拼图      # 先看列表状态
<venv python> tools/mfa_zero_task.py --run --task 每日魔幻拼图 --max-wait 240
```

- 规格要选 **「6x6（4x4图片）」**（实例配置里 `每日魔幻拼图规格.index = 2` 就是它）。
- `mfa_set_puzzle.py` 走 **UIA `ValuePattern.SetValue`**，**窗口最小化也能写**（不受坐标哨兵值影响）；
  写完会逐框回读复核，16/16 一致才算成功，失败会打印原值供回滚。
- 写完可以顺手核对 MFA 是否已落盘：`config/instances/default.json` 里 `每日魔幻拼图位置6x6` 的 16 个值 + 文件 mtime。
- ⚠️ **逐个填写位置不会被「60 秒重随机」坑到**，因为 MFA 的执行是一次性的、而且重随机只在未落子时发生；
  真被重随机了，位置串会失效 → MFA 的 Swipe 就会把盘面越弄越乱。**所以开局到执行之间别拖太久**。

## 三-bis、2x2（4 块 / 4×4 棋盘）求解流程（照做）

> 下面是 2026-09-14~18 打通的老路径，**4 块档仍然有效**。16 块档请走上一条 §三。

0. **先把命令准备好**，再截图——链路越短越好（规则 8）。
1. **截图** → 用 `../../scripts/piece_identify.py` 识别 4 块在哪：
   `python piece_identify.py shot.png --tpl-dir <拼块模板目录> --xs 431,570,709,847 --ys 150,288,427,565`
   - 若这一步是**新图案**（没有现成模板），先做「定正确排布 + 出模板」，见第 2 步与第五节。
2. **定正确排布 + 出新图案模板**（已脚本化，一条命令）：
   `python ../../scripts/piece_numbering.py --idle 未开始.png --shuffled 打乱后.png --xs 431,570,709,847 --ys 150,288,427,565 --out-dir <目录> --prefix <图案名> --label <图案名>`
   - **原理**：**未开始帧的中央 2×2 就是正确排布**，只是正中压着 ▶ 圆钮 → 用圆形掩膜挖掉；再拿 24 种排布跟它做 **NCC（归一化互相关）**。
   - ⚠️ **起始页那张图不能当「模板」**去匹配拼块（是缩略预览，明暗/尺度都不同），**但可以当「标准答案」**。
   - ⚠️ **别用 MAE 打分**：两帧亮度差会把信号淹掉（24 种排布全挤在 75~78）。
   - ⚠️ **判空判据**：脚本默认用 `彩色像素占比 + 灰度std/100`（拼块 vs 中性灰遮罩）。
     **别退回「饱和度均值」**——2026-09-16 的星空鱼块饱和度均值只有 55~70，被判成灰格，只找到 2/4 块。
     万一自动判块仍不对：`--cells "r1c2,r1c3,r3c4,r4c4"` 手动指定。
   - ⚠️ **`▶` 圆钮会污染「左下块」模板**（2026-09-18 首次明确）：▶ 位于中央 2×2 的**偏左下**位置，
     把 **3 号（左下）块**大半遮成灰色，只留一条黄绿边。
     后果：该块在识别时的 `diff` **天然偏高**（本局 47，其余 3 块仅 1.3~2.4）。
   - ★ **判定纪律（照这个来，别硬设 diff 阈值）**：
     **只要「其余 3 块 diff < 5 且互不冲突」，剩下的那一格就是它**——不要因为某一块 diff 大就重试。
     脚本 `pz_auto.py` 已按此放宽为「3 块小 diff 校验」。
   - 兜底 / 交叉验证：把候选排布拼出来看图——正确的那张是一条完整连贯的鱼。
   - ⚠️ 「未开始帧」和「打乱后帧」**必须是同一局**。
3. **BFS 求解**：
   `python ../../scripts/line_shift_solver.py --n 4 --at "A=2,2 B=3,2 C=4,2 D=4,4" --shape "TL=C TR=A BL=D BR=B"`
   （默认目标锁**中央 2×2**，这样「任意位置」和「回中央」两种判定都能满足。）
   - ⚠️ 求解器打印的「目标: 2x2 左上角 = (1, 1)」是**文案 bug**，实际算的是 `center`（n=4 → (2,2)）；
     校验方法：看它输出的**终局状态**是否落在 r2c2/r2c3/r3c2/r3c3。
4. **按解逐步 `input swipe`**（800~1000 ms），**每步或每 2~3 步截图复核**（用第 1 步的脚本再识别一次）。
   - ★ **手势映射公式（2026-09-18 首次明确验证，5 步全中）** —— **拖动式：手指方向 = 内容移动方向**：
     | 步骤 | 手势（XS = 431,570,709,847；YS = 150,288,427,565） |
     |---|---|
     | 行 r **左移 k** | `swipe(XS[3], YS[r-1], XS[3-k], YS[r-1])` |
     | 行 r **右移 k** | `swipe(XS[3-k], YS[r-1], XS[3], YS[r-1])` |
     | 列 c **上移 k** | `swipe(XS[c-1], YS[3], XS[c-1], YS[3-k])` |
     | 列 c **下移 k** | `swipe(XS[c-1], YS[3-k], XS[c-1], YS[3])` |
     （即：行操作固定用最右列 `c4` 作起点/终点，列操作固定用最下行 `r4`，跨 k 格距离滑，天然避开中心区域。）
   - 复核不符 → 大概率是自动重随机抢先了一步：**停手，回去第 1 步重新识别重算**。
5. **拼成即停**：出现「完成」印章 / 彩带（约 3 秒后弹奖励窗）→ 本次自动化结束。**不点奖励窗任何东西**（见红线）。
