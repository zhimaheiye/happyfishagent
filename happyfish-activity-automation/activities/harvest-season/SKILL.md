## 三、★★ 核心纪律：先合，合到无可合，才允许发射

芝麻 2026-10-06 09:0x 原话：

> 「**盘面挤满+无同类可合，这个其实说明你的操作是有问题的。我看你好像是合成一会你就开始花体力往棋盘上加新的东西，但是这个其实应该合并到盘面上没有东西可以合成的时候再去放新东西，这样按理来说其实不会出现挤满的情况。**」

正确循环（**判据是"还有没有可合的对"，不是"空格够不够"**）：

```
现拍一张 → fs_match 签名分组
  ├─ 场上还有任意一对"同级可合"  → 一直合，合到全盘找不出一对为止   ← 不许中途去发射
  └─ 一对都找不到（真·无同类可合）
        ├─ 空格 > 3      → 这时才发射（点稻草人 (1160,585)）
        └─ 空格 ≤ 3      → 提资源 / 删低等级小资源件腾位（§5 已授权），再回第 1 步
```

**我上一轮把"腾出 4 个空格"当成去发射的信号**，等于主动把没合完的低级件埋回盘里，越烧越塞 → 占格爬到 43~45/48，被游戏自己的 toast 挡死（§4）。

### 3.1 同等级贝币**先互合，别单枚提取**

芝麻 2026-10-03 原话：

> 「体力必须烧到0和贝币最高等级才能提取，这两个并不冲突啊……**如果同等级贝币是同时出现的，你应该把贝币之间互相合成，而不是单独把它们提取啊**」

→ 提取只在**真要腾位**时用。低级件（右侧面板明写「几个贝币 **等级1**」这种）正是该互合的那一类。

### ⭐ 本轮新验证的 4 条硬规律

**1. 拖拽时长必须 ≥1400ms。** 900ms 会被游戏吞掉 —— 本轮连续 3 次「合法合并」返回 NO CHANGE，换成 1400ms 后同一条 swipe 立刻生效。配合 `--wait 3.0~3.5`。

**2. ⭐ 同等级直线拖拽 = 合并，且距离没有上限。** 不再需要"先摆相邻"：
- 跨 **3 格**（r1c5 → r1c2，中间两格都有子）合出 一篮小麦 L9 —— `fs_131_merged.png`
- 跨 **4 格**（r3c4 → r3c8）与钱袋换位 —— `fs_155_drag4.png`
- 跨 **空格**（r2c5 L4 → r2c7 L4，中间 r2c6 空）合出 成熟小麦 L5
- 跨 **3 格、途经 3 枚占用格**（r2c1 L1 → r2c5 L1）合并

→ **这条直接推翻了 §六 里"L3+L3 到底能不能合尚未验证"的保留意见：能合，而且根本不用相邻。** 之前所有"L3 合不动"的记录，真因是**当时全盘 48/48 无空格、又误以为必须相邻**。

**3. 合并会在周边随机空格"吐"奖励子。** 不是"揭开正上方"（见下条更正）。实测样本：

| 触发合并 | 冒出来的新子 |
|---|---|
| L8+L8 → L9 | r3c2 一罐玉米粒、r3c3 手套、r3c4 萌芽小麦 |
| L4+L4 → L5 等一连串 | r1c5/r1c6/r1c8/r3c8 多枚 **1枚贝币**、r3c6/r4c8 种子袋、r4c7 手套 |
| 麦种合并链 | r4c7 手套、r4c8 种子袋 |

→ **贝币/种子袋这类资源件主要靠合并产出，不靠发射。** 发射 22 次几乎只给小麦 L1/L2。

**4. ⛔ 彩虹泡泡 ≠ 棋子。** 被合并腾空的源格、以及刚出现的新子，会套一圈彩虹光晕。**光晕格可能是空的**：本轮两次把泡泡误读成实体棋子，导致拖空。
→ 判据：`celldiff` 里泡泡格常报 **frac 0.8+** 但**目标格零变化**；或再拖一次它，若只有源格变、对面不动 = 泡泡，不是子。

###  已推翻的旧结论：「合并会揭开正上方那格」

原 §四 那条（落叶堆是覆盖层、合并揭开正上方）**不成立**。它建立在 2 个样本上，本轮又采了 3 个样本全部指向**"合并往周边随机空格吐新子"**，而不是"揭开某一固定方向的覆盖格"。
**根因**：开局那 40 格"落叶堆"其实是**未解锁的空格底纹**，清盘后它们就是普通空格 —— 我当时把"空格开始落子"误读成"覆盖层被揭开"。

### 发射产出的等级

本轮 22 次发射的落子统计（`fs_159`/`fs_163`/`fs_171`）：**小麦种子(1) 与 萌芽小麦(2) 混合，偶见青苞小麦(3)**，与盘面最高等级**无关**。
→ 旧记录里"发射 = 最高级 − 1"的猜测**作废**，正确说法是 **发射产出 L1~L3 混合，偏低等级**。

### ⭐ 两类棋子，提取时机完全不同（芝麻口述 + 实机确认）

| 类别 | 判据（**看绿箭头，别看文案**） | 例子 | 正确用法 |
|---|---|---|---|
| **链条件** | 格子**没有**绿色上箭头 | 小麦链全部、烘焙链全部、成长豆苗 | 只管往上合 |
| **资源件** | 格子**有**绿色上箭头（脉冲动画） | 1枚贝币 / 2枚贝币 / 一些贝币、种子袋 | **一路合到最高再单击提取**；低级时别点 |

- 绿箭头是**脉冲动画**，所以逐格 diff 在资源件上会常年报 0.05~0.16 的假变化。
- 10-01 实测提取回路：5 枚 1枚贝币 + 1 枚 2枚 + 1 枚 一些贝币 → 5 步拖拽合到最高可得档 → 单击 r5c8 → **棋子消失、⚡ 不扣、面板回到「点击棋子以阅读详细信息。」**（`fs_177_extract.png`）。
  ⚠️ **到手的贝币数额没有核实**（要退出活动看主界面 HUD 才知道），记为**未验证**。

### 逐格 diff 判读口径

```bash
python tools/celldiff.py BEFORE.png AFTER.png --min 0.20 --half 46
```
- `frac > 0.20` = 这一格真的变了；`0.05~0.16` = 绿箭头脉冲噪声。
- **发射落子只报 0.23~0.28**（小棋子占 92px 窗口比例低），别当成噪声。判"发射有没有落"要 **数变化格数 == 发射次数**，并核对 ⚡ 掉了几格。
- ⚠️ **r1/r2 有飘叶动画**，永远 `| grep -vE "r1 c|r2 c"` 之后再判读。
- ⚠️ 列号务必照 `291/391/491/591/691/791/891/991` 数，**591 = c4**。
