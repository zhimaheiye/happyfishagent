# 活动留档契约

日期：2026-10-06。

这份契约给**正在操作模拟器、帮用户处理活动的 Agent**。先读完再点第一下。

用户要的不是“这次活动被点完了”。用户要的是：以后写 MaaHappyFish 自动化时，不用再把这个活动重玩一遍，就能知道当时每一屏长什么样、点了哪一个、为什么点它、旁边还有什么、以及哪些情况这次没碰上。

**活动玩完，但下面要求的文件没有落在会被 git 跟踪的路径里，这次活动就不算做完。** 在对话里说“我看过了 / 我点过了 / 素材按理应该有”，不算记录。

主技能 `SKILL.md` 的纪律 B 只要求“一步一截图、记下坐标”。那是底线，不够。截图堆在仓库根目录，或者只留在被 gitignore 的 session 里，下一次拉取、下一位 Agent、写自动化的人都看不到。

## 1. 什么文件才算留下了

只认这两处，而且必须提交到本仓库 `happyfishagent` 的 `main`：

| 放哪里 | 放什么 |
|---|---|
| `assets/<活动>/` | 整屏截图、从**这一页这一状态**裁出的模板、一份 README。README 用中文写每张图是哪一屏、分辨率、图里稳定的是什么。 |
| `happyfish-activity-automation/activities/<活动>/SKILL.md` | 动作表和分支表。每一行都能对上 `assets/` 里的文件名。 |

下面这些**不算**留下了：

- 仓库根目录的 `_*.png`、`shots/`、`*.shot.png`。这些是临时图，不入库。
- `activities/<活动>/sessions/`。`record_action.py` 的 session 被 `.gitignore` 忽略，只是当场草稿。
- 只存在于对话、记忆或另一台电脑上的描述。
- 从别的活动、别的页面、别的缩放状态裁来“看起来很像”的图。

`record_action.py` 继续用。它负责当场留下 before / after、设备坐标和 1280×720 坐标。活动结束前，把以后写自动化还要用的截图、裁图和决策**抄进上面两处**，再提交。草稿留在 session 里就结束，等于没抄。

本仓库只产出素材。不要把这些文件写进 `D:\happyfishgame`，不要替用户改 MaaHappyFish 的 Pipeline。

## 2. 每一次点击，当场记这 8 项

点下去之前先写。点完再补最后一项。漏一项就补，不要等整局结束再靠记忆回填。

1. **这一屏是什么。** 整屏截图，文件名能看出活动、步骤、页面。写明分辨率。本机约定是 1280×720；若不是，写实际宽高，不要把另一分辨率的坐标当成 720p。
2. **这一屏上读到的原文。** 按钮、标题、说明、角标、搜索框里的字，按画面上的字记。不要改写成自己的理解，不要用颜色外号代替文字。
3. **这一屏上你考虑过的每一个控件。** 每个都有一行：原文、大致位置、这次点还是不点、为什么。决定不点的按钮也要记。以后的自动化靠这些行做开关和熔断。
4. **实际点中的那一个。** 识别框 `[x, y, w, h]` 和中心。坐标来自 OCR 框或在原图像素上量到的中心。对话里被缩小的预览图不能直接当坐标。
5. **为什么是它。** 写出你用来区分它和旁边控件的稳定特征：原文、位置关系、固定图案。只写“点了下面那个”不够。
6. **预期下一屏是什么。** 用你会在下一屏看到的标题或固定控件来写。
7. **点完之后的整屏。** 和预期一致就写一致；不一致就写实际变成了什么，以及你接着怎么处理。
8. **这一下有没有消耗。** 体力、次数、金币、贝币、开心宝、广告、对外发送、不可逆确认。没有消耗也写“这一下不消耗”。

滑动、长按、输入文字同样记。输入要留下**实际打进去的字符串**，以及当时屏幕上有哪些候选项、点中了哪一个、没点哪些。

## 3. 模板怎么裁

模板是给以后的图像匹配用的，不是“把这一页留个纪念”。

- 从**将要拿去匹配的那一页、那一种状态**上裁。主界面图标、展开后的图标、选中态图标分开裁。
- 裁到固定、下次还会长一样的部分。数字、倒计时、游动的鱼、粒子、活动装饰不要进模板。袋子、图标下面的数量会变时，只裁不含数字的上半部分。
- 裁完打开 PNG 看一遍，确认没有带上相邻按钮和圆角外的背景。
- 圆形或小图标以后要点识别框中心，档案里写中心，不写一个靠角的固定点。
- 同一屏有多张看起来相近的结果时，每张都留裁图，并写明这次点的是哪一张。例：搜索只输入「虎鲸」，结果里要记下蓝色和旁边其它结果各自的样子，以及点的是蓝色那条。
- 不确定某块像素下次还会不会一样，就不要把它当成模板。在档案里写“这块不稳定，未采模板”，把整屏留下供人判断。

不要把真人头像、邀请码、玩家 ID 放进文档或模板。

## 4. 分支和没出现的情况

自动化要处理的是“可能遇到什么”，不只是“这次运气好走到了哪”。

每一段流程用一张表：

| 情况 | 这次是否出现 | 画面上的原文 | 对应截图 | 以后怎么处理 |
|---|---|---|---|---|
| 正常下一步 | 出现 | … | `assets/.../03.png` | 点「原文」 |
| 付费 / 广告 / 开心宝 / 纸币 | 出现或未出现 | … | … | 不点 |
| 二次确认、不可逆、对外发送 | … | … | … | 默认停，问用户 |
| 空列表、次数用尽、已领取、按钮还亮着 | … | … | … | 按这次看到的写；没看到就写“本次未出现” |
| 点了没反应、网络错误、弹窗挡路 | … | … | … | 写实际现象；没遇到就写“本次未出现” |

“本次未出现”和“游戏里没有这种情况”是两件事。没见到就写未出现，不要写成不存在。

旧档案和这次实机不一致时，以这次实机为准改档案，并写明旧路径错在哪一屏。例：海獭入口若档案写的是宝箱再到皇冠，而这次实际从另一条已有素材的路径进去，就要改掉旧路径，不能两套并写还让下一位 Agent 继续走错的那条。

同一种活动若有两种合法走法，两种都写清楚，并写各自从哪一屏开始。不要用新走法覆盖旧走法，除非用户明确说旧走法作废。

## 5. 结束前的自检

下面每一项都能用仓库里的文件回答，才可以说这个活动本次做完了。

- 从哪一屏开始，经过哪些屏，最后停在哪一屏。每屏有整屏图。
- 每一步：看见什么、点了什么、为什么点这个、点完变成什么。
- 同一屏上没点的控件：原文、位置、为什么不点。
- 入口和回到主鱼缸的每一步，包括有没有二次确认。
- 搜索、多结果、多品质、多类别：输入的原文、点中的结果、旁边没点的结果。
- 可能出现的付费、广告、不可逆、空状态、已领取、网络错误：有表，没遇到的写“本次未出现”。
- 需要以后做图像匹配的控件，有从当页裁出的模板，并在 README 里说明裁的是哪一部分。
- 这些文件在 `assets/<活动>/` 和 `activities/<活动>/SKILL.md`，不在仓库根、不在 `sessions/`。
- 已经提交并推送到 `happyfishagent` 的 `main`。只留在本地未跟踪文件里，也不算做完。

## 6. 和现有红线的关系

付费、广告、开心宝、不可逆操作，仍然不点。契约要求的是**把它们认出来并记下来**，不是为了留档去点它们。

探索仍只点导航、页签、关闭和只读视图。会消耗次数、货币或对外发送的按钮，先记原文和位置，拿不准就停下来问用户。问的时候把已经留下的截图路径一起给出。

已经验证过的固定入口可以按主技能的盲连击走。盲连击的前提是这条路径的每一步截图、坐标和理由**已经在本契约说的位置里**。新的一屏、新的按钮、新的浮层，仍然先截图再点。
