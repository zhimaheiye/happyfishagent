# Agent 工作模式、MAA 所有权与兜底边界（V1 · 2026-10-11）

> **规范性入口，所有游戏操作前必读。** 当前用户委托 > 本文件中的模式与任务所有权 > `activity-authorization-resource-flow.md` 的游戏货币分层 > 子技能里的历史动作表。对历史日志/坐标的记录不赋予新授权。此规则约束 **happyfishagent**；不改变 **MaaHappyFish** 的工作方式。只读审计可展开，任何实际点击前还须走游戏资源/界面安全门禁。
>
> 关键定义：**MAA 日常收尾的任务所有权归 MAA**。不管当天 MAA 有没有运行、有没有勾选、有没有正常完成、是否曾报错，Agent 默认都不接管。**OFF、未运行、没看见成功日志、页面有红点**均不自动触发补做。用户负责正常查看其报错与日志；Agent 只在本次明确授权的兜底范围内介入。

## 1. 首先判模式，不得中途自己扩权

| 模式 | 触发 | 允许 | 禁止 |
|---|---|---|---|
| **A 日常执行** | “做今天 Agent 负责的日常”“清已授权的短期活动免费次数” | 按下节固定流程执行**已有授权、确定非 MAA 负责**的任务；充分利用免费体力与玩法内材料；收集最终领奖处信息 | “清全屏红点”“把所有左栏都点完”；对任何 MAA 日常收尾子任务补做、重启或排障；自选最终常驻奖励 |
| **B 功能探索／开发** | 用户指定研究、取证、开发某功能 | 只读仓库、对照现有功能、界面导航、枚举候选、截图/裁模板/建分支表；若任务明确授权测试某个**具体玩法和所需投入**，才执行对应有成本的步骤 | 把“其他所有功能也看看”解释成全部执行一遍；为了素材试买、试送鱼、试用稀缺次数；擅改 MAA 稳定实现 |
| **C MAA 定点兜底（附加授权）** | 用户本次**明确授权**对某 MAA 任务或限定故障类型兜底，可叠加 A/B | 先只读日志定位**真实失败**、核对是否已成功执行，优先走 MAA 本身安全重试/修复路径，在授权边界内最小恢复 | 把“兜底”当长期自动接管权；因未运行/OFF/红点就补；主动停止正常队列、重跑全部日常或绕过 MAA 的资源/识别门禁 |

**专项排除项：许愿神灯**。除非用户本次明确指令指定“许愿神灯”，否则 A 日常、B 广泛探索、C MAA 兜底**都不准主动进入**。仅被明确要求看页面，也不能擅自消耗普通绸/金绸；消耗还需要当前明确的资源类型和次数上限。见 [`wishing-lamp-special-authorization.md`](wishing-lamp-special-authorization.md)。**此禁令高于一般活动集合授权和 A/B 免费资源分层。**

**模式 B 的“范围广”只放宽阅读和取证覆盖面，不放宽点击和资源权限。** 用户话语含糊时以更窄的无损动作推进并记录未决事项。新发现的问题单列候选，不自动加入当次计划。

## 2. MAA 任务归属清单：名单从代码配置读取，不能用旧 18 项日志代替

**权威来源**：`zhimaheiye/MaaHappyFish` 远端最新 `assets/interface.json` 的 `DailyRoutineTask` → `日常收尾任务.cases`，必要时查 `docs/features/daily-routine.md` 和对应具体模块/全局功能。2026-10-11 核对的可选**17 项**（是**配置可选项**，不代表当天全开启或全执行）：

| 组 | MAA 日常收尾可选子任务（均归 MAA 所有） |
|---|---|
| 奖励、社交与任务 | 每日免费礼包、驯鹿鱼送收礼物、兑换金贝壳券、绿野寻仙踪日常、公主任务 |
| 小游戏 | 乐队鱼、金海豚、摇一摇、钓鱼达人、浪漫满屋祝福 |
| 兑换与订单 | 宝石礼盒兑换、宝石订单 |
| 培育及鱼缸资源 | 购买鱼食、鱼宝乐园、魔力召唤、宝石融合 |
| 活动体力专项 | 领取活动体力（酿月食香；旧活动已结束，仍属已有 MAA 功能） |

**另有 MAA 独立任务/全局处理，不能因未出现在上表就擅自接管**：例如 `SeaDiveTask` 深海寻鱼（**已有功能但尚不完善**）、`DailyMagicPuzzleTask` 魔幻拼图、`SeaOtterGemTask` 海獭摸宝、`FriendGemTask` 好友摸宝，以及全局签到/弹窗处理；以最新源码和配置核实实际覆盖的子流程。**“好友摸宝”和“海獭摸宝”不是同一个功能**，不能混称。未列入日常收尾也可能是 MAA 独立功能。

同名页面可能有不同**具体子流程**：如「浪漫满屋祝福」（MAA 日常子任务）与另一个独立的约会玩法不是自动等同。必须按**子操作**核对 MAA 是否覆盖和 Agent 是否得到专项授权；不确定时不双跑、不重复领奖。既有单独日程的授权也需按其自身范围执行，不能由“清红点”重建。

### 两项指定功能的现行分工（2026-10-11 用户补充）

- **深海寻鱼**：MAA 已有 `SeaDiveTask` 等相关能力，**功能尚不完善**。当前先保存 `activities/sea-dive/SKILL.md` 和 `assets/sea-dive/` 的导航、截图、免费/付费态素材，留待**用户下次按这些素材开发完善，并将该功能补充到 MAA 的「日常收尾」**。这是未来开发计划，**不是 Agent 此刻开工、自动代跑或擅自更改 MAA 的授权**。只有用户另行点名具体调查/开发时才按 B 模式做对应事项。
- **每日魔幻拼图**：**从全部主动日常/定时/红点清理任务移除**，但保留图像识别、拼块标号、位置串生成及核验脚本和全部历史素材。用户**明确要求出拼图编号时**，Agent 才针对指定的**现有拼图图片**做只读分析，交付编号/位置串及可靠性判断，低置信结果明示需复核；**不进入游戏、不开始或移动拼图、不写 MFA 输入串、不启动/停止 MFA、不选择或领取奖励**。如用户未来专项改变任务范围，再单独判定；此前历史“可代领经验”不适用于当前出串任务。
- 这两项的技术材料仍然有价值，禁止因为「不自动执行」而删除旧图片、编号算法、动作记录或对应子技能。**知识和能力可保留，执行授权独立判断**。

**状态判断与行为**：

| 观察 | 默认动作 |
|---|---|
| MAA 子任务 ON 且正常结束 | Agent 不重复做；无需每天代查每个子任务 |
| MAA 子任务 OFF、当日未运行、手动停、无日志 | Agent 不把它当作漏做；不重启、不补任务 |
| MAA 某一步失败 | 用户自行处理正常告警；Agent 只读报告可以在被要求排查时提供，但**默认不接管** |
| 独立/全局 MAA 已覆盖一部分 | 剩余部分**必须单独核对**能否安全切分，未确认不执行 |

不要修改 `MaaHappyFish` 的默认开关、任务队列或正式 Pipeline 来“配合 Agent”。若用户专门委托修改 MAA，则另按开发工作流处理，不能偷换成游戏日常授权。

## 3. 日常模式 A：固定阶段 + 显式任务清单，红点绝不生成任务

按顺序执行，**阶段不可因为红点/当前所在界面而跳转去做未授权的事**：

0. **本次委托和互斥检查**：确定模式、用户授权的任务清单、MAA 归属，核对 MFA/模拟器有无正在操作；运行中不可抢输入。
1. **只读发现**：基于既定清单确认日期、免费次数、活动是否存在和是否被 MAA 覆盖。要判断“精彩活动”成员，使用大厅真实卡片标题 + 活动内日期 + 入口标题交叉核对；**大厅巡检本身只读**。
2. **按固定清单完成 Agent 自己的工作**：当前优先级槽位为 **① 明确委托的非 MAA、临期免费限时玩法；② 已被单独授权且核实不受 MAA 覆盖的固定小活动（例如薰衣草旅馆）；③ 本次用户额外点名的非 MAA 项**。每槽内按本次维护的清单顺序，不按红点位置排序；名单空则跳过。新的入口或小游戏仅记候选，除非可由“精彩活动短期玩法”的有效**集合授权**确认纳入。活动材料仅按资源分层 A/B 自主消耗，最终兑换 C 保留用户选择。
3. **只读最终兑换与截止提醒**：记录余额、候选、价签、游戏截止和领奖截止（若已证实），尤其最后 48 小时提醒用户选择；**不能自行清空货币**。
4. **闭环留档与报告**：按契约留前后图、动作/消耗/未点击分支；报告“MAA 拥有未处理”“Agent 已做”“最后领奖待用户选”“未授权/缺证据跳过”。不得声称未经核验的 MAA 项已做或未做。

**尚未建立永久完整的 Agent 日常项目清单**。以上是**固定阶段/已有示例槽位**，不是给所有示例新增每日执行授权；需按当前委托、既有专项授权和实际 MAA 覆盖组装本次清单。特别是“未读红点全清”“看见就顺手做”“日常收尾 OFF 的都补”均禁止作为任务生成逻辑。

## 4. 模式 B：广泛调查，但以证据验收为终点

- 用户指定**一个功能**：先查两仓最新文档、实现、是否属于 MAA 所有、已存在素材；从任意实际 UI 起点识别，按授权范围调查。
- “把别的功能也看看”：允许扩大**只读**候选清单（活动名、入口、归属、已有材料、缺失点）；不自动启动其他玩法，不更改它们的 MAA/Agent 任务配置，也不自行花掉它们的次数。
- 一份功能调查必须交出 **覆盖矩阵**：入口与退出、每屏前后图、控件原文及 bbox/坐标、没点的危险按钮、可能分支、消耗变化、模板裁切和适用条件、待验证状态；素材落在 `assets/<活动>/` + `activities/<活动>/SKILL.md` 的**可追踪文件**，按 `activity-evidence-contract.md` 检查，并推送远端。
- **工作状态严格分级**：`surveyed_readonly`（只读调查）、`gameplay_observed`（有实机流程证据）、`assets_committed`（素材及文档确实入库）、`maa_ready`（已验证可供自动化使用）；没有对应实物不能称完成。未遭遇的分支标“本次未出现”，不能写已验证。
- 不为了收集素材擅自消耗一次性机会/货币；已获授权的实际免费玩法按 A/B 层并留证；需用户决策的最终领奖仍禁止代选。

## 5. 允许 MAA 定点兜底的严格前提

必须**同时**满足：① 这次用户给出对应任务/故障类型的兜底授权（有可核验范围）；② 最新 MAA 日志证明该步骤**真正失败**而非仅 OFF、未运行、用户停止或已完成；③ 截图及日志确认没有已经成交/领取，重试**不会重复不可逆动作**；④ 不与正在执行的正常 MFA/人工操作抢控制；⑤ 恢复动作使用 MAA 已有安全门禁、明确限制最多一次且有验收依据。无法满足任一项：记录失败与证据，**不点击、不自行重跑**，等用户处理。

先分析再决定是否需要执行，不因报错立即重启游戏/队列。不能为了找日志而默认干涉游戏；对已有守护脚本的历史行为介绍不等于给当前 Agent 执行该脚本的许可。**任何自动恢复/定时任务应单独经过用户授权与冲突审查。**

## 6. 每次操作的留痕与校验

执行日志至少记录：`mode`、`task_id`、`source`（用户指令或确定的集合授权）、`maa_owner`（含具体子步骤）、`action_type`、`resource_in/out`、`safety_gate`、`screenshot_before/after`、`result`、`evidence_path`。未经批准的项记 `skipped_out_of_scope`，而不是“失败待补”。

### 离线权限预检（无设备副作用）

`../scripts/task_scope_policy.py` 提供 **纯 Python、无 ADB/模拟器调用** 的规划决策示例；`../tests/test_task_scope_policy.py` 包含 MAA OFF/未运行、失败未授权、明确兜底、探索只读、最终兑换、未知花费与运行冲突等用例。在仓库根目录执行：

```bash
python -m unittest discover -s happyfish-activity-automation/tests -p 'test_task_scope_policy.py' -v
```

测试只读取人为传入的 `Proposal` 字段；它**不会自己核实用户授权、画面 OCR 或 MAA 日志**，也未接任何真实点击通道，因此**不能作为实际点击前的最终许可**。

**这是操作规则，并非自动强制的运行时权限闸**：Recorder 仍依赖 Agent 自报 `--safety`；当前尚未把本文件与所有 ADB / MCP / MFA 操作通道进行硬拦截绑定。离线规则测试只验证决策契约；不能据此宣布模拟器的实际越权点击已被代码彻底防止。
