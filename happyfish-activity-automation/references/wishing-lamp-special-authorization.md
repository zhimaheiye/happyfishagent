# 许愿神灯专项授权边界（2026-10-11）

> **高优先级特殊禁令。** 这是一个**默认完全排除**于 Agent 自主日常、限时活动集合授权、红点清理、广泛探索和 MAA 兜底的常驻功能。只有用户针对**许愿神灯本身**发出明确指令，才可按该指令有限处理。历史操作记录、机制、坐标、MAA 实现和“以前允许过”都是**知识资料，不是当前授权**。

## 1. 默认动作：不主动进入，更不擦灯

- 日常执行、精彩活动、左栏巡检、红点清空、免费次数最大化、活动快结束、素材采集、MAA 失败兜底、其他功能顺手调查，**都不赋予进入许愿神灯或消耗许愿绸的权限**。
- 默认不要点击许愿神灯图标进入该页，不点击任何「许愿绸」「许愿金绸」「擦灯」「看视频擦神灯」及其它可能消耗许愿资源的按钮；既不能花 1 次普通绸，也不能花 1 次金绸。
- 如果它已经出现在当前截图/左栏，允许**识别并登记名称**，但不主动点入、不开启流程，也不报告“未做/需要补做”。查现有仓库的机制文档与历史截图属于**离线资料查阅**，不触发游戏操作。
- 如果是其它已授权任务误跳进此页，**暂停后续点击并先识别现场**；只有确认安全的退出方式才可离开，不能顺手擦一次灯、清红点或看广告。

## 2. 什么才算授权

| 用户的当前表述 | 当前权限 |
|---|---|
| “做今天日常”“把免费活动做了”“左栏有红点都看看”“顺便把功能都研究一下” | **无许愿神灯执行权**；不进入 |
| “把许愿神灯资料整理一下”“解释普通绸/金绸的机制” | **只读文档/历史截图**；不进入游戏 |
| “打开许愿神灯给我看看页面” | 仅本次**进入、查看、截图及安全退出**；不消耗普通/金绸 |
| “今天用 2 次普通许愿绸，不用金绸” | 仅本次、核实真实界面和资源后，最多消耗 **2 次普通绸**；不能换金绸，不能额外买次数 |
| “许愿神灯你自己处理” | **未明确资源类型/数量和边界，不得自行消耗**；先记录需要明确的项目 |

**进入授权 ≠ 消耗授权。** 消耗时必须能从当前明确指令核实：具体使用普通绸还是金绸、可消耗的最多次数、活动/页面身份。未提的资源类型视为**未获授权**；次数没说也不可按“花到用尽”自定上限。即便已经获具体授权，依旧不得花开心宝、人民币、看广告或触碰其它不明付费项。必要时停在边界并询问。

**即便用户本次允许使用普通绸，也不能自行切到金绸**；即便历史资料写了“先刷倍率再用金绸效果最好”，这也只是策略知识，不能代替本次对金绸的明确授权。

## 3. 与其它授权的关系

1. 本专项禁令**优先于**任何一般性的免费玩法 A/B 资源层、活动范围、旧 SKILL 中的可执行步骤、通用“导航安全”、成本低/免费、自动收尾、MAA 兜底或历史许可。只有用户本次对许愿神灯的**明确指令**可以改变对应步骤的权限。
2. 如 `MaaHappyFish` 已实现或部分实现相关功能，任务所有权和模拟器互斥规则**仍要另外核对**。专项授权不会自动授予启动/停止 MAA 队列的权限，也不会赋予修改稳定 Pipeline 的权限。
3. 许愿神灯的操作策略、曾误点金绸坐标以及 2026-10-11 擦掉 3 次普通绸的事故继续作为历史**证据**保留，前方必须标注“禁用于未授权运行”。
4. 离线 `task_scope_policy.py` 只验证调用方**声明**的 `feature_id`、专项允许状态、资源类型和次数。它无法识别真实游戏按钮、读取用户原话、校验次数累计，**且未接到所有 ADB/MCP 点击通道**；不能称之为运行时强制拦截。

## 4. 反例与验收

- `scope=assigned, resource=A, feature_id=wishing-lamp` + “免费日常” → **拒绝进入/点击**；
- 同样在功能探索模式、只想收集素材 → **拒绝进入**，但可离线阅读资料；
- 本次只授权**查看页面** → **允许查看，不允许消耗任何绸**；
- 本次授权**普通绸 x2** → **绝不能使用金绸**，不能把上限擅自改成 x3；
- 已有 MAA 兜底许可或 MAA 报错 → **不能当作许愿神灯专项许可**；
- 旧“先普通绸刷倍率、再金绸”的攻略 → **仅记录，不自动执行**。
