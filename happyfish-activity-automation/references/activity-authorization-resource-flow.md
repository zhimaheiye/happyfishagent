# 精彩活动授权与资源流转规则（V1 · 2026-10-11）

> **规范性规则，优先于各活动 SKILL 中的旧处置口径。** 历史动作表、坐标和实测证据可以保留，但“当时做过 / 觉得可以 / 够就兑 / 活动币花光”不能当作未来授权。
> 用户当次明确指令优先；**但执行模式与 MAA 任务所有权先按 [`agent-work-modes-maa-boundary.md`](agent-work-modes-maa-boundary.md) 判断**。本文件只控制已进入合法任务范围的“精彩活动”短期玩法的**资源流转与最终兑换权限**，不能凭 A/B 免费消耗规则越过 MAA 的任务所有权。其他常驻系统需各自授权。

## 1. 先判范围：授权的是一类活动，不是左栏所有入口

当用户委托“精彩活动里的短期活动”时，允许 Agent 为已核实属于该集合的**限时玩法**自主推进，不要求用户逐个念出活动名称。核实方法：

1. 进入“精彩活动天天有”**只读枚举卡片**，取**活动标题**，与已有活动子技能、主鱼缸左栏或其他入口的真实标题**交叉核对**；进入限时玩法前读规则/标题里的起止日期、是否确有免费玩法/次数。
2. 只认**同一活动**的入口映射，不凭坐标、红点、左栏位置、图标颜色或“看起来像活动”扩权。集合页里也有商店新鱼、人民币礼包、兑换码、常驻签到和外链等卡片：**在大厅 ≠ 自动获玩法授权**。
3. 无法确认“该卡片属于受托的短期玩法”时，只登记标题、页面、疑点并跳过这项；其余已确认项目继续执行。常驻公主任务不得借“临时活动”口径被顺手处理；**许愿神灯则由 MAA 独占，Agent 无论是否点名都不进入或消耗绸，相关素材已删**。其它专项禁令（如海獭摸宝）也不被集合授权覆盖。
4. 如果用户**只授权巡检/对账**，就仅枚举、留证，不进入玩法。明确受托“完成精彩活动里的限时免费玩法”才进入下面的资源循环。

## 2. 再判动作：看资源在链路中的用途，不能看名字或“有没有价签”

`每日免费次数/体力 → 活动内小游戏 → 中间道具/材料 → 更多活动内操作 → 活动货币 → 最终领奖处 → 常驻资源`

| 层 | 举例 | 默认行为 |
|---|---|---|
| A. **游戏免费投入** | 每日赠送的活动体力、免费碗、免费剪刀、免费行动次数 | ✅ 已核实是免费获得、仅用于受托活动的额度后，可自主消耗到没有安全且有价值的免费玩法；不得为了“清零”去买次数。 |
| B. **玩法循环中的中间材料** | 活动本局所得的太阳、刺刺球、浇水道具等，用于开下一关、解锁本局必要环节 | ✅ 只要**消耗与产出都在受托活动的玩法循环里**、不扣账号通用资产，Agent 可自行优化用量，不必每步问；有多种走法可自己判断。 |
| C. **最终兑换池/奖励选择** | 领奖处、去领奖、兑换页：把活动货币换成金币、图纸、拼图、常驻资源、鱼或其他长期持有物品 | ⛔ **Agent 只读余额、货架、价格、库存、截止时间，不主动发起交易或点击成交确认**；无论便宜还是昂贵、是否有足够余额、是否最后一天。等用户明确选择物品和数量后才执行所授权的兑换。 |
| D. **账号长期存量** | 开心宝（含“钞票/纸币”等别名）、人民币、常驻珍珠/宝石/金币、稀有道具、鱼苗/成鱼/皇冠鱼等 | ⛔ 不借用活动任务擅自消耗、赠送、出售、丢弃或兑换。已有其他子技能的具体历史授权不能自动推及新活动。 |
| E. **广告/真钱/不明成本** | 蓝色 ▶ 看视频、¥购买、额外购买体力、未知或可疑扣费、付费复活/加速 | ⛔ 不点；遇到未知成本暂停这一动作并保留证据。 |

**判定靠经济效果而不是按钮名字。** 某“中间商店”如果换的是继续推进本次小游戏所需材料，可按 B 处理；如果交换后永久获得账号可用的物品，或需要你在数件常驻奖励中选一件，则按 C 处理。名称叫“领取”也未必安全，名称叫“兑换”也未必是最终兑换。

**免费随机五选一宝箱（2026-10-11 用户明确允许）**：在已授权的临时玩法中，若各箱本质是**随机盲选**，其中明确有一个**0 付费/0 通用长期资源**的免费机会，Agent 可任选该免费箱开出随机结果并收下，作为玩法内奖励；另外四个带钞票/开心宝等价签的箱子、一次性全开等全部不点。即使随机箱直接掉落一条长期鱼，**免费抽取本身仍被本次授权允许**。但若各选项明确展示了**不同永久奖品的内容、价值或消耗有限的已攒活动币**，则仍属于用户保留的最终奖励选择，必须停手；无法识别哪个箱子免费也停手。

**无需代选的固定免费产出**（任务达标后“领取 x1”、通关确定、已经免费获得的宝箱固定掉落）可正常收下；**明确展示永久奖品的多选一，或消耗可囤积活动货币以换长期物品**，属于用户的最终选择。历史「某活动固定选经验」偏好不能用于当前每日魔幻拼图——它现行仅按需输出识图标号。

一旦分类不清，不要用廉价商品测试，不要把“零开心宝”当成有权兑换；**停在该节点并继续其他安全玩法**，回报疑点，不得用“性价比好”“能买得起”“快过期”代替授权。

## 3. 防止活动到期损失：最大化生产，保留最终决策

- 正常日常：优先用掉当天会刷新/失效的免费次数和活动内材料；记录尚未完成的免费入口、活动货币余额、最终领奖处候选。不为消耗货币而乱兑换。
- 每次巡检核对真实截止时间及是否存在独立的“只可领奖”窗口；**不能把别的活动的 24 小时领奖期套用到新活动**。
- 进入**最后 48 小时**或已知最后一个可游戏日时，主动在本次报告里突出提醒：活动名、玩法截止、领奖截止（若已证实）、余额、候选常驻物品及价格、哪些选择需要用户拍板。若没有常驻监控任务，不能声称会在未来自动推送。
- 即便截止只剩几分钟，未获用户指示也**不得默认兑换**。实在来不及，要明确说明“最终兑换待你选择；到期可能失效”，并保留已挣到的资产与证据。

## 4. 执行前 / 执行后最小检查

**执行前**：先读模式/MAA 归属规则 `agent-work-modes-maa-boundary.md`，再读主 `SKILL.md`、本文件、匹配的活动子技能；写下“用户授权哪一类活动 / 核实到的活动名称 / 这一步消耗什么且产出什么 / 属于 A-B-C-D-E 哪层”。**用户没有委托的内容不能由文档或历史记忆代为授权。**

**执行后**：逐步留截图 + 坐标 + 前后计数（见 `activity-evidence-contract.md`）；汇报时分开列出：① 已完成的免费玩法、② 已消耗的活动内投入、③ 保留的最终兑换货币、④ 待用户选择的领奖处、⑤ 截止时间和不确定项。已发生的越权消费如实标记，不能写成“主动规划”“故意攒着”。

## 5. 审计反例（必须能判对）

- 公主任务赏金珍珠 **710→122**、树袋熊梦梦 **588**：常驻活动未纳入委托，而且最终兑换未经授权；**禁止**。就算价签只要 **18**，仍然禁止擅自试买。
- “快到碗里来”已有免费碗用于切水果：**允许**；“去领奖”用水滴/水果币换图纸/拼图：**用户先选**。
- “刺刺大作战”已送的免费次数、真正用于推进关卡的活动材料：**允许**；“领奖处”花晶石/小花换鱼或常驻物品：**用户先选**。
- **许愿神灯：完全归 MaaHappyFish**，Agent 一律不进入、不擦绸、不代跑、不尝试任何领奖操作；不设通用日常/探索/专项授权例外。之前误用 3 次许愿绸是事故反例，不是任何未来操作的依据。
- 临时活动今天结束：**提醒领取期限与可选奖励**，不能据此自动清空兑换币。

> 当前 Recorder 的 `--safety` 和 `--reason` 主要靠 Agent 自报，尚不能可靠识别画面上的真实经济语义或绑定用户授权。本文件是操作约束，**不代表代码层的强制拦截已完成**；后续需要独立的执行闸门与回归测试。
