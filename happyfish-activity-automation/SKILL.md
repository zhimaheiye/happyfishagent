# 开心水族箱 · 活动自动化（主技能）

把「新活动 → 摸清规则 → 稳定自动刷完免费资源」这套流程固化下来。目标是一次学会、下次直接上手，而不是一次性脚本。

**本技能是主技能**：这里管「怎么干」（通用流程 / 环境 / 红线）；具体活动的界面、规则、坐标放在 `activities/<活动>/SKILL.md` 子技能里。

## 三条硬红线（任何情况下不破）

1. **绝不点付费按钮**。界面按钮右上角带**蓝色 ▶ 圆标 = 看广告**（本机跑不了，等于废）；带开心宝图标/数字 = 付费。两者一律不点，哪怕卡住。
   - ⚠️ **★ 形态不能当判据（2026-09-14 差点出事故）**：深海寻鱼里「**x6 修复潜艇**」的浮空框跟「金币 x100」这种**免费可拾取物长得一模一样**（同款橙色圆角框 + 数量角标），**但它是花 6 个开心宝的付费按钮**。当时我写下"怀疑这是免费道具"，幸亏只裁图读字没去点。
   - **新出现的浮空框 / 道具 / 按钮，一律先按"它是付费的"默认假设处理**；读出文字确认后才可能碰。
   - **"救援型"商品默认全是开心宝**：修复、补充、续命、复活、加速、解锁 —— 见到就当付费。
   - ⚠️ **货币别名要核实（2026-09-16）**：课间休息把开心宝叫「**纸币**」！底部提示「本次点击需要消耗：纸币 x2」＝ 花 2 个开心宝。**没有"免费"二字的一律先当付费**；同一界面若别处写着"消耗 N 开心宝"且图标同款，可直接互证。**免费额度耗尽后的"续点/续命/翻倍"几乎必然是付费**。
   - 拿不准 → **不动手，报给用户**。宁可少拿奖励，不能误花。按钮文字读不清就放大 3~4 倍读（`scripts/zoom.py`）。
2. **不可逆操作先刹车**：花钱、删数据、对外发送 → 停下来问人，别猜。
3. **每次点击/拖拽前先截图确认界面**。禁止链式盲点；关闭类按钮（X / 取消）尤其要多看一眼。拿不准含义 → 先放大读文字，读不清就问。
   - **唯一例外**见下节「盲连击」：**已经实测验证过的固定导航路径**才允许省略中途截图。

## ★ 卡住时的第一反应：回文档，别自己编（2026-09-17 芝麻明确要求）

**操作没达到预期时，按这个顺序走，不要跳到「我猜是……」：**

1. **先停下来读文档** —— 本文 + 对应活动子技能 + `references/automation-playbook.md`。
   - 09-17 我花了**两个多小时**在一个「通道坏了」的假设上，而那个假设**文档里根本没提、纯属我自己编的**；文档早就写着答案（「格子只接收空位，已有内容的格子会拒收」）。
2. **再查是不是自己的坐标 / 判据错了** —— 目测坐标？拿旧截图当基准？整屏 diff 被动画骗了？网格没重标？图标认错？
3. **归因必须给证据** —— 给不出证据就写「**待验证**」，别写结论（见下节「三层诊断」）。
4. **只有 1、2 都排除后**，才考虑环境问题（通道 / 模拟器 / 别的进程抢占），而且要用 `input tap` 这类**最小实验去验证**，不能假定。
5. **仍然不确定 → 停下来问用户**。他最清楚现场，而且明确说过「拿不准就问」。09-17 正是芝麻一句「**你停下来的位置那里不是空的，所以当然就弹回去了**」点破了我两小时的死结。

> 一句话：**文档 > 自己的推理 > 自己的猜测。** 卡住的时候，先翻文档。

## 盲连击：已验证路径可以「不截图直接连点」（2026-09-16 芝麻要求）

芝麻明确要求：**别每步截图识别，用保存好的坐标直接连点**。这条路走通了，但要严格限定条件：

- **只对「已实测走通一次以上」的固定导航路径使用**（入口 → 弹层按钮这种）。
- 进新界面 / 新按钮 / 新浮层 —— **红线照旧，必须先截图**。
- 一条命令串起来，间隔 0.5s：
  ```bash
  adb shell "input tap 905 593; sleep 0.5; input tap 910 417"
  ```
  - adb shell 内部 `sleep` 可用；⚠️ **本机 Windows 侧的 `sleep` 命令是坏的**（PATH 缺失），要等待就用
    `python -c "import time;time.sleep(3)"`。
- **走完立刻截图验收**：位置对了才继续，错了就停下来重新定位（别连续猜）。
- ★ **没进去就重试，别停下来分析遮挡**（2026-09-18 芝麻原话：「**用盲点坐标和画面验证，没进入就重试**」）。
  - 典型翻车：入口图标被**游鱼/流水动画**周期性遮住 → 点在鱼身上没反应。
    正确反应 = **原坐标重试点几次**（鱼游走的瞬间就命中），**不是**去裁图研究"到底该点哪一块"。
    09-18 我为此连裁 6~7 张图、换了 5 个坐标，最后靠盲连击一次成功 —— 纯属浪费。
  - ⚠️ 注意区分：**"重试" ≠ "乱改坐标"**。坐标是实测过的就坚持重试；
    若连续 3~5 次都失败，**才**去查是不是界面变了（对照子技能的界面指纹）。
  - ⚠️ **重试 ≠ 连点：先确认控件不是「开关型」**（09-16 血泪）：珊瑚点一下展开气泡，**再点一下就把它收回去**——我想着「连点两次提高命中率」，结果亲手把气泡收了。**命中型**目标（按钮/格子）可以重试；**开关型**目标（展开/收起、选中/取消）点中第二次 = 撤销上一次。分不清就点一次、截图看状态再决定。
- **"看起来该中却没中"时，用颜色扫描求 bbox，不要反复目测**：
  对**原图**做颜色 mask → 连通域 min/max → 中心。
  09-18 用这招把执行按钮从"目测 955,652"纠正到真实 **(1066,672)**，**目测偏了 110px**。
- 实战战绩：浪漫满屋「珊瑚 → 气泡 → 大厅 → 约会 → 通关 → 退出」全链路一次点通；
  深海寻鱼「切缸 → 潜艇 → 进图 → 三连返航」09-18 盲连击一次点通。

- 很多活动藏在二级面板里：

## 到达终点即收手（不代选、不代领）

玩法跑完（拼好、清空、通关）后**立刻停手**，把界面交给用户：

- **奖励多选一 / 领取按钮一律不点**。不同人偏好不同（金币 vs 经验 vs 材料），脚本无权替玩家决定。
- 需要的话只把候选奖励和坐标**记录在子技能里供人工参考**，并在输出里说明「已停在选择界面，请自行领取」。
- 唯一例外：用户**当场明确说了**选哪个、且这一步可逆，才按指示点。
- 通关类弹窗（纯提示、不含奖励选择，如浪漫满屋的「确定」）可以直接点掉。
- 用户已明确的今日约定：**每日魔幻拼图通关后立即收手，不选卡、不点领取**。

## 主循环（每一轮都走）

0. **先确认挂机状态**（2026-09-17 新增）：挂机（MFA 任务队列）随时会把模拟器抢走 ——
   做事前先看 `tools/guard_status.txt` 或 MFA 日志，**挂机在跑时别拿 adb 去点活动**，两边会打架。
   另：挂机"断线"多半是**游戏卡在需要人拍板的弹窗**上，不是模拟器崩了 → 第一步截图看当前界面。
   详见 `references/automation-playbook.md` **第七节**。
1. **连设备** → maa-mcp `find_adb_device_list` → `connect_adb_device`，拿到 `controller_id`。MCP 返回空/`false` 时立刻改走 adb 兜底（见 `references/automation-playbook.md`）。
   - MCP 若一直是 `Still connecting`（未就绪），**不要干等**，直接走 adb 兜底；adb 通道全程够用。
2. **截图** → 一张全屏定位，再按关键区域截若干张。
3. **放大读图** → 判读图标/文字**必须放大 2~3 倍**（`scripts/zoom.py`），绝不凭缩略图猜。
4. **单步操作** → 一次只做 1 个动作（拖拽 / 点击），做完立刻截图核对变化。
5. **闭环验证** → 有可见变化（计数 +1、格子清空、卡池变少）才算这一步成立。
6. **记账** → 规则与**进/出导航**写进对应子技能；验证过的坐标才入库，没验证的标「待复验」。改完仓库后按仓库 README「更新与同步」收尾：push → 校验远程 main → 同步回 `~/.workbuddy/skills/` → 逐一校验一致（技能有两份生效副本，漏一步，下次加载的就是旧经验）。

## 关键操作：拖拽 / 滑动

活动小游戏大量用「把道具卡拖进格子」或「滑一行/一列」。

- maa-mcp：`swipe(start_x, start_y, end_x, end_y, duration=2000)`
- adb 兜底：`adb shell input swipe x1 y1 x2 y2 1600`

拖**卡片**要**慢拖**，落点取目标格中心附近。

### ⚠️⚠️ 操作「没反应」的三层诊断（2026-09-17 血泪，别再把锅甩给通道）

09-17 我连续十几次把「拖拽后画面没变」判成「adb / MCP 输入通道坏了」，还顺手编了「MFA 独占通道」「这游戏不吃合成手势」这类解释 —— **全是错的**。拖拽一直有效，真因是**落点不合法 → 卡片原路弹回 → 最终画面和操作前像素一致**。芝麻一句「你停下来的位置那里不是空的，所以当然就弹回去了」直接点破。

**按 ①②③ 顺序查，别跳步：**

| 层 | 症状 | 判据 / 处置 |
|---|---|---|
| ① **落点** | **卡池张数不变，且目标格 / 全盘零变化** | 落点被拒 —— 格子只收**空格**（已有内容 / 混合格 / **锁格 🔒** 一律拒收，同色也拒）→ **卡片原路弹回，且不消耗**（09-17 四次实测：混合格 / 已占格 / 污染格 / 锁格，卡池张数**都没变**）。**换一个空格重拖** |
| ② **起点** | **落点已确认是空格，卡池还是一张没少** | 起点没落在图标上 = 拖拽根本没触发。放大截图量图标真实中心（`scripts/find_objects.py`），**同一个坐标绝不重试第二次** |
| ③ **通道** | 真的没送达 | **先用 `input tap` 点一个无害位置**（背景 / 空白）：画面有反应（冒字、涟漪、切界面）= 通道是好的 → 回到 ①② |

> ⚠️ ①② **症状相同**（都是"卡池没少"）→ **先查落点合法性，再查起点精度**，别跳步。
> 还有一层**机制性前提**：某些游戏**盘面内的元素本身不可拖动**（浪漫满屋即如此）→ "把挡路的牌挪走"不是可选项，**动手前就要算清空格预算**（第三节第 12 条）。

- ⚠️ **★「点击有效但拖拽无效」这个组合几乎不存在** —— 二者走同一条通道。一旦你觉得自己遇到了这个组合，**100% 是你的判据有问题**，不是工具。09-17 我在这个假问题上耗掉两小时。
- ⚠️ **★ 别把「通道坏了」当第一假设**：它是最贵的假设（会引出一串没必要的重启 / 重连 / 换工具 / 改脚本），而且实测几乎总是错的。**先怀疑自己的坐标和判据。**
- ⚠️ **★ 归因必须给证据（09-17 最重的错）**：要说「X 导致 Y」，先拿出 X 的直接证据（截图 / 日志 / 命令输出）；拿不出就写「**待验证**」。
  - 我编过的假解释：「浪漫满屋大厅的水波和飘落的公告条干扰了判定」—— **那个界面根本不存在这些东西**，是我为了圆「点击无效」凭空想出来的。
  - **宁可说「我不知道」，也不要编一个听起来合理的因果。** 芝麻对「默认假设未陈述的事实」是零容忍的。
- ⚠️ **MCP `swipe` / `click` 返回 `true` 不代表操作生效**（多次实测返回 true 而盘面零变化）。**唯一确证是截图 + 前后状态对比**，不是工具返回值。
- 卡槽 / 列表类 UI 在**不补位**时会漂移：剩余张数不同，位置就不同 → **每次以截图为准，别背坐标**；能用工具测位就别目测（见 `scripts/detect_pool.py`）。
- **起点的精确求法**：卡池图标的中心必须用「4×4 降采样 + 8 连通 flood fill 求 blob 质心」，**目测 / 带标尺裁剪都会偏 20px 以上**（09-17 实测：目测 (1142,262) 落在图标左上边缘 → 拖拽静默失败；blob 质心 (1161,261) 一次成功）。

## ★ 操作前的三条默认纪律：基准帧 / 语义判据 / 每帧重标（09-17 血泪）

**每次动手前先默认这三条成立**，它们各自都能单独毁掉一轮操作。

### 1. 判「变了没有」，只能比「紧邻的前后两帧」
- ❌ 我拿「十几分钟前刚进界面时拍的 `q1.png`」当基准去比 —— 期间界面早被游戏改过 / 被我动过，**所有判读全乱**。
- ✅ **规矩：每个动作前拍一张、动作后拍一张，只比这两张。** 旧截图只能当"当时的现场记录"，不能当基准。

### 2. 整屏像素 diff 有「动画噪声」，判生效要用语义判据
- 卡池卡、需求卡都有**轻微呼吸浮动**，两帧整屏 diff 会冒出 3k~5k 的**假差异** —— 我就被它骗出过「卡池补卡了、盘面大变了」这种结论（实际零变化）。
- ✅ **判「操作是否生效」只看语义量**：**卡池张数**、**完成日程 N/10**、**目标格内容**。
- 像素 diff 只用**逐格定位**（`scripts/diff_cells.py` 的「未变格 = 0.0」仍然可信），**不用来下结论**。

### 3. 网格坐标一律用脚本求，别在像素数据上手推
- **实测结论：该界面列 / 行都稳。** 列 `298 / 427 / 543 / 659 / 775 / 891 / 1007`（间距 116），行 `182 / 296 / 410 / 524`（间距 114）—— **四张不同时刻的截图，脚本跑出来完全一致**。
- ⚠️ **但我手推的那版是错的，还编出了假规律**：我从「蓝色连通段」手工推导，得出 `q1` 的行是 168/284/400/516，随后又把这当成"另一帧的值"，倒推出「**行会漂 13px**」这个结论 —— **纯属自己算错，再给错误配了个原因**。
  - 真因：**行与行之间的缝隙只有约 5px**，比卡片内被图标打断的缺口（约 30px）还小 → 任何"合并连通段"式的手工分行都必然出错。
  - 正确做法：找**第一行卡片顶**（最靠上的蓝色像素），再按固定行高往下推。
- ★ **规矩：坐标一律用 `scripts/calib_calendar.py` 求，不要自己在像素数组上手推。** 手推出来的"规律"很可能本身就是错的，而且会连累后面所有判断（这次就白写了一条不存在的纪律）。

滑**整行/整列**用 800~900ms 即可，**滑动方向 = 内容移动方向，滑动距离 = 平移格数**（先量出格距，再换算 px）。

## 坐标法

- ⚠️ **★ 坐标一律取 OCR 的 box，禁止在截图上目测。** 截图原图是 **1280×720**，但对话里看到的预览被缩到 **1080×608** —— 在预览图上目测出来的坐标**必须 ×1.185** 才是设备真实坐标。
  - 血泪案例（2026-09-14）：点「知道了」目测 (550,431)，实际 OCR box 中心 (637,505)，**偏了 (87,74)**，比例 1.16~1.17。当时误判成「MCP click 失效」，其实是尺子量错了。
  - **出现偏移先算比例**：`实际 / 目测 ≈ 1.185` → 就是缩放坑。芝麻的原话：「我给你提供的坐标是对的，你要想一下自己之前是点的哪里、为什么会有这个偏移」——不要只盯这一次。
  - 任何点击/滑动后**必须闭环验证**（数值变了 / 弹窗关了），不能假定成功。
- ⚠️ **★ 网格坐标用「连通域 / 颜色扫描」求，别拿预览图目测换算（2026-09-16）**：预览缩放的误差有几十像素（曾导致连点两空格）。正确做法：对**原图**做颜色连通域或投影扫描，输出的中心才是设备真坐标。工具见 `tools/find_objects.py`。
  - 也可用来判「两个图标是不是同一个东西」——09-16 正是靠它锁定「纸币＝开心宝」。
  - ⚠️ 但**连通域 bbox 会被相邻的同色装饰污染**（09-16）：求浪漫满屋退出按钮（心形 X）包围盒时，把按钮**左侧的粉色装饰**一起圈了进去 → 中心算出 (1171,50)，比真值 (1199,52) 偏左 28px。**先剔除干扰块，再裁剪放大目视复核中心**，两步都过了坐标才算定死。
- 先全屏截图定出网格中心点，**列/行各一套等差坐标**，后续所有操作按「格号 → 坐标」换算。
- 每个活动把坐标表写进它的子技能，下轮直接用。
- 参考：1280×720 下 MuMu 的常见日历网格 ≈ 列 `298/427/543/659/775/891/1007`（间距 116），行 `~181/296/410/524`（**行会漂 ±13px，每帧重标**）。旧记 301/427/544/660/777/893/1009 是同一套值（±3px），列基本可信。
- ⚠️ **★ 找不到目标时，先回去读文档里的坐标，别在截图上自己量（09-17 血泪）**：浪漫满屋大厅的「一起约会吧！」文档明写 `(1069, 581)`（**浅绿半透明胶囊**），我却在截图上目测出一个粉色块当成它，点 `(910,480)` 连点 6 次「没反应」—— 然后又去编「MCP click 失效」「通道坏了」。
  - **规矩：文档里已有验证过的坐标时，读它，不要重新发明。** 重新标定的前提是"文档里没有 / 实测明显不符"，不是"我懒得翻"。
- ⚠️ **★ 图标命名必须靠「并排对比图」定死，别凭印象（09-17 血泪）**：我整轮把盘面上的**橙色方块小人**叫成「相机」、又归到「非需求色」，而它**就是需求列第 1 张的「机器人」**（真相机是**浅绿白方块**）。代价：误判「机器人盘面上一个都没有，这槽需求做不了」，白绕一大圈。
  - **规矩**：每局开局先把**需求列 3 个图标**和**盘面出现的每个图标**裁出来拼成一张**并排对照图**，命名定死再算可行性。
  - **本期形状规律**：绿**方块**=相机 ／ 绿**圆球**=绿壶铃(KG)；橙**方块**=机器人 ／ 橙**圆球**=橙壶铃(KG)。**同色不同形，只有轮廓能区分。**

## 通用技巧

- **格线用像素扫描量**，别目测：沿棋盘取一条干净的横/纵带，求亮度中位数，**暗的局部极小值就是缝隙线**；残余的格子边界不受左上角反光干扰时要换一条带再量。
- **界面静止时（连拍两帧像素零差异）是最佳工作条件**：此时任何变化都能当作「动作生效」的确证。
- ⚠️ **★ 判「哪一格变了」一律用差分，别目测（2026-09-16 血泪）**：把两帧按格子逐格算平均色差，**没变的格精确是 0.0**。我用目测多次把「根本没变的格子」说成变了，还把两格变化脑补成四格，全靠差分才纠正。工具：`scripts/diff_cells.py`（默认浪漫满屋 28 格）。
- ⚠️ **★ 截图有时效，界面会被游戏自己改写（2026-09-15 血泪）**：拼图**未落子前盘面每 60 秒自动重随机一次**（logcat `MiniGameController::tryToRandNewGame()`，间隔精确 60 s；我 15:57 截的盘面 15:57:32 就作废了）。凡「截图 → 慢分析 → 再执行」的流程：要么**一口气 60 秒内跑完**，要么**执行前重新截图复核**——别拿一张几分钟前的图当真。
  - 2026-09-16 又测了一次：点开始后 97 秒盘面**纹丝不动**（逐格模板识别 diff=0.0）。触发条件仍不明 → **纪律不变，永远按"截图会过期"来安排**，复核一帧的成本远低于拼错重来。
- **★ 界面「自己变了」先取证、别猜（2026-09-15）**：按 `uptime`（模拟器重启没）→ `ps -A -o PID,ELAPSED,NAME`（App 重启没）→ `dumpsys window | grep mCurrentFocus`（在哪个界面）→ `logcat`（真正原因）四步查，**读 logcat 要按时间窗过滤 + 把数字归一化成 `#` 做「形态去重」**。完整方法见 `references/automation-playbook.md` 第六节。踩坑：我第一反应猜「模拟器备份恢复把游戏重启了」——**猜错了**，真凶是游戏的 60 秒定时器。另：**MuMu 前端会周期性崩溃自愈重启**（`restart-guard/` 里每多一个 `rg-*.txt` 一次），属常态，别误判成用户操作。
- **认块用模板匹配**：先在一个已知状态把每块裁成模板存档，之后每步截图拿 16 格去比，diff 最小者即该块（见 `scripts/piece_identify.py`）。
- **环形/滑动类排列题一律 BFS 求最短解，别手推**（见 `scripts/line_shift_solver.py`）。开局随机 → 每轮重新识别 + 重新求解。
- ⚠️ **起始页/预览图不等于拼块本体**：预览是缩略图，明暗尺度都不同，**别拿它当模板**去匹配拼块。但它能当**标准答案**——挖掉压在上面的按钮后，用 NCC 比对着反推正确排布（见 `scripts/piece_numbering.py`）。
- **比图形用 NCC，不要用 MAE**：跨帧/跨状态的明暗差异会把 MAE 信号彻底淹没（实测 24 种排布的 MAE 全挤在 75~78，差 0.6 纯噪声）；NCC 自带亮度归一化，正确解立刻拉开到 0.93 vs 次佳 0.53。
- **被 UI 盖住的部分用掩膜挖掉**：参考图上压着按钮/弹窗时，按几何位置生成圆形/矩形掩膜，只在未遮挡像素上比对。
- ⚠️ **判「这块是内容还是背景」别只看饱和度均值（2026-09-16）**：灰底遮罩是**中性灰**，而"深蓝星空"这类图案**饱和度均值不高、彩色像素却很多** → 用 sat 均值判空会漏掉它（实测自动阈值 86.2 只找到 2/4 块）。
  改用 **`彩色像素占比 frac(sat>40) + 灰度std/100`**：拼块 1.33~1.54 vs 灰格 0.14~0.27，断层 1.05，干净利落。详见 `scripts/piece_numbering.py`。
- ⚠️ **辨图标看形状，不能只看颜色（2026-09-16）**：浪漫满屋里「相机」（绿色**方形**）和「绿壶铃」（绿色**圆球**）同色不同形，我按颜色误认了整轮，导致归因全错。**先看轮廓，再看颜色**。
- **"僵尸图标"要单独设处置策略**：总出现却永远不被需求收走的元素（如浪漫满屋的相机），对策是往边角格堆到 5 让它自己成大日程**锁死在角落**，不占活跃格。
- ⚠️ **★ 汇报要跟实际操作对得上账（09-16 芝麻）**：芝麻原话「我看你的输出是你要去点珊瑚，但你却误打误撞点进了气泡，我其实不太确定你是怎么到现在这个结果的」。每步写清「**点了哪里 → 屏幕变成了什么**」，让芝麻能跟着复盘；连自己都复盘不出怎么走到这一步时，**直说「我搞不清刚才点到了哪」，别硬编一个连贯的故事**（同「宁可说不知道，也不编因果」）。

## 资源

- `scripts/grab.py` — adb 截图到 ASCII 隔离目录（规避 adb 不认中文路径）
- `scripts/zoom.py` — 局部裁剪 + 放大
- `scripts/burst_tap.py` — **连拍 + 定时点击**：抓「一闪而过」的文字（进图瞬间的地图名等），~4.5 fps
- `scripts/frame_diff.py` — 帧间差异，从连拍里定位「剧变帧」
- `scripts/crop_scan.py` — 批量裁同一区域并挑最清晰的一帧
- `scripts/sweep_move.py` — **边走边拍**：滑动与连拍同时进行，帧间 MAD 掉到 ≈0 即「画面停住 = 撞墙/被挡」
- `scripts/piece_identify.py` — 按模板识别棋盘上每格是空位还是哪一块拼图
- `scripts/piece_numbering.py` — 用「未开始帧」反推正确排布，把拼块按左→右/上→下编号并导出 MAA 可用模板（自动判块用「彩色像素占比 + 灰度std/100」；失灵可 `--cells` 手动指定）
- `scripts/line_shift_solver.py` — 整行/整列循环平移棋盘的 BFS 求解器
- `scripts/detect_pool.py` — **卡池槽位测位**（浪漫满屋右侧 3 槽）：扫描饱和天蓝底，输出每张卡片的 y 区间与图标中心坐标，免目测换算
- `scripts/diff_cells.py` — **两帧逐格差分**（默认浪漫满屋 28 格）：精确列出哪几格真的变了，未变格 = 0.0
- `scripts/calib_calendar.py` — **日历网格自动标定**（浪漫满屋）：一条命令输出 4 个行中心，并校验 7 个列锚点。**坐标别再手推了，跑它。**
- `tools/mumu_dev.py` — **★ 实例号 → adb 设备串**（走 MuMuManager 的 `adb_port`）。**别再各自 `pick_device()` 取「第一个」**
- `tools/mfa_guard.py` — **★ 挂机守护**：每 1 h 体检 模拟器/adb/游戏进程/MFA 队列，只有硬异常才自动恢复（四条安全阀）
  > 队列恢复两条路：环境刚修过 → 跑整队列；环境本来就好 → **右键失败任务「单独运行」→ 跑完 → 点「开始任务」**（第七节 7.2.1）
  > 上面两个在**项目根目录** `D:\开心水族箱活动经验\tools\` 下（不在本技能的 `scripts/` 里）。
- `references/automation-playbook.md` — 环境、双通道连接、兜底命令、读界面纪律、红线表、**挂机运维与守护（第七节）**
- `activities/<活动>/SKILL.md` — 各活动玩法事实
